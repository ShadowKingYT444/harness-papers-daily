## What is actually new

This paper asks a useful null question:

> **How much explicit harness machinery does a strong modern coding agent actually need?**

Under matched model, hardware, and 24-hour budget, the largest improvement comes from giving the model a practical coding environment—shell, filesystem, execution feedback. Adding fixed search trees or simple multi-agent orchestration does not show a clear extra benefit.

The novelty is not a new harness. It is a controlled test of whether "more scaffold" still helps frontier models.

## Mental model

Older models often needed strong external decomposition because they could not sustain long autonomous work.

A strong coding model may already:
- inspect files;
- write a plan;
- test hypotheses;
- revise;
- keep local state.

If the harness re-implements those same behaviors with extra search/control, it can add cost without adding capability.

This creates a high bar for RHEvolution. Adaptive decomposition must provide information or search structure the model does **not already create effectively inside its own session**.

## Key objects and controls

- **Backbone model:** held fixed in matched comparisons.
- **Coding-agent environment:** shell + filesystem + execution.
- **Malena:** simple long-running single-session agent.
- **Search primitive:** greedy/UCB/Best-of-N-style outer search.
- **Multi-agent variants**
- **24-hour compute/hardware budget**
- **Validation process:** reused across candidates.
- **Selection gap:** difference between best candidate generated and one selected.

## Step-by-step experimental logic

1. Pick one strong model.
2. Fix machine/hardware and wall-clock budget.
3. Give every condition the same task definition and evaluator.
4. Start with a practical coding-agent environment.
5. Measure the marginal gain from each extra harness layer.
6. Compare multiple fixed search strategies under the same budget.
7. Compare single-agent and simple multi-agent variants.
8. Repeat with released MLE harnesses across several backbones.
9. Report uncertainty, not only best-run score.
10. Distinguish generation quality from selection quality.

## What the study finds

The coding-agent environment is the largest clear intervention.

Once the strong model can:
- read/write files;
- execute code;
- inspect results;
- continue for a long session;

the tested fixed outer search methods do **not** show a statistically clear universal advantage.

Simple multi-agent variants also do not show a clear consistent gain.

The paper's minimal Malena setup is competitive with or better than several more structured systems depending on backbone.

## Why this is a serious baseline

A complex harness has costs:
- more tokens;
- more failure surfaces;
- extra coordination;
- more code to maintain;
- more assumptions about how the model should reason.

If a frontier model internally creates an adequate plan and test loop, explicit orchestration can duplicate work.

Therefore "more structured" is not synonymous with "better engineered."

## The selection-gap lesson

Search can generate a strong candidate and still fail because it selects the wrong one.

This echoes Mid-Harness and harness-evolution studies: proposal quality and selection quality are separate bottlenecks.

A tree with many candidates only helps if:
- the search reaches distinct useful solutions;
- evaluation can identify them;
- the added compute beats spending those tokens on one strong trajectory.

## Failure modes and limits

- The study focuses on autonomous ML engineering; other domains can need stronger external structure.
- Fixed search strategies are not the same as learned/adaptive decomposition.
- A 24-hour budget can favor long single-session methods.
- Null statistical results do not prove zero benefit.
- Weaker models may benefit more from explicit harness structure.

## Implementation checklist for a RHEvolution null baseline

Build a minimal condition with:
- same frontier model;
- shell/filesystem;
- long context/session;
- normal built-in planning/tool use;
- no adaptive decomposition.

Match:
- wall-clock;
- token budget;
- environment;
- retry budget;
- evaluator.

Then compare RHEvolution at equal resource cost.

## What RHEvolution should take from it

This paper forces the research question to become sharper.

Do not claim:
"Structured harnesses help agents."

Test:
"Does adaptive ownership/decomposition provide **additional OOD gain or search efficiency** beyond what a strong frontier agent already does inside a minimal coding harness?"

Also stratify by solver strength. RHEvolution may provide larger value for mid-strength models and smaller value for the frontier. That is a result worth reporting, not a failure.
