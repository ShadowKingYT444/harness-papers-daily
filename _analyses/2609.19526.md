## One line
Tree-search RSI is bottlenecked by expensive benchmark evaluations, so SIFT replaces per-patch evaluation with pairwise LLM-judge comparisons aggregated by a regularized Bradley–Terry model, disaggregates expansion from evaluation, and matches or beats DGM/HGM on Polyglot at roughly a tenth of the compute.

## The problem
Recursive self-improvement of coding agents works — Gödel Agent, SICA, DGM, HGM all show it — but the search loop is brutally expensive: every candidate self-modification must be validated by re-running benchmark tasks, which the paper notes can cost upwards of $22,000 on SWE-Bench and thousands of CPU hours. Full benchmark evaluation is reliable but slow; subset evaluation is cheap but noisy. The paper identifies the signal-to-cost tradeoff of per-patch evaluation as the primary bottleneck and proposes a cheap intermediate signal: an LLM judge rating proposals pairwise.

## How it works
SIFT (built on the DGM harness) has two coupled ideas. (1) **Pairwise judge + Bradley–Terry aggregation.** Each new candidate patch is compared pairwise against incumbent agent harnesses by an LLM judge; the win-loss record feeds a regularized Bradley–Terry model that assigns a global strength score to every node in the search tree. Pairwise calls cost a few cents each — an order of magnitude cheaper than a full Polyglot-50 evaluation — and are calibration-free compared to absolute rubric scoring. (2) **Fully disaggregated tree search.** Expansion and evaluation run as separate parallel streams: parent nodes are sampled from the full archive with weights combining BT rank, accuracy rank, and a visit-count exploration term, while a priority queue of nodes-to-evaluate is ranked by the same metric. An orchestrator inserts finished expansions into the evaluation queue, prioritizing high-potential nodes while launching the next expansion — judge scores guide speculative exploration so the search never stalls waiting for slow benchmark runs. Expensive full evaluations are reserved for the most promising nodes only.

## Key results
On Polyglot-50 with Qwen3-30B as coding model and Qwen3-480B as expansion/judge model, 30 evolution steps lift accuracy 16% → 38%, and the best descendant reaches 31.1% on the full 225-task Polyglot at $34.3 API cost, 6.71h wall clock, 224 CPU hours — stated as a tenth of the DGM baseline's cost. Head-to-head on Polyglot-225: SIFT 31.1% vs HGM 30.5% (at 347 CPU hours) vs DGM 27.1% vs SICA 25.1% vs base 20.0. With o3-mini as coding model, SIFT reaches 35.1% within 30 expansions vs DGM's 30.7% after 80 tree-search nodes, in under 5h wall clock, 42 CPU hours, $150 API — and three repeat runs land in [32.0%, 35.6%], consistently beating DGM at lower cost. The discovered harnesses transfer: re-evaluating SIFT-discovered harnesses with gpt-5-mini and gpt-5.4-mini as coding models still improves Polyglot performance.

## How it relates to adaptive decomposition
The transferable insight is about *evaluation budgeting*, which is the scarcest resource in any harness-evolution loop including the user's. Adaptive decomposition gives each component an independent search budget — the question is how to spend it without burning full benchmark runs on every candidate. SIFT's answer is a two-tier signal: a cheap, noisy judge for ranking plus expensive validation reserved for the top of the queue. That maps directly onto per-component evaluation: use a cheap LLM-judge pairwise comparison to decide which component revisions deserve full harness rollouts. The BT aggregation is also a cleaner alternative to the binary keep/reject gates used elsewhere (cf. VACE's validation gate): a scalar strength with uncertainty, aggregated over pairwise evidence, is exactly the kind of ranking signal a successive-halving-style budget allocator wants. One caution for the user's setting: SIFT's judge compares whole-harness patches, so it inherits the monolithic credit-assignment problem — the judge can't tell you *which* component made the patch better.

## Limits and open questions
The authors are explicit about the main ones: SIFT still depends on downstream benchmark evaluations for final validation — the judge is a ranking accelerator, not a replacement. The judge in the strongest runs is *stronger* than the coding backbone (Qwen3-480B judging Qwen3-30B), so this isn't pure self-judgment; whether a smaller or open-weight judge (or the coding model itself) gives comparable ranking signal is untested. The Bradley–Terry model assumes pairwise outcomes are explained by a single latent strength per node — a useful approximation for search, but it hides task-specific tradeoffs (a patch that helps long-horizon debugging while hurting syntax repair gets one scalar). The paper suggests multi-dimensional or failure-category-conditioned rankings as future work. Finally, the usual RSI caveats: safety and evaluation-integrity risks of self-modifying agents, noted but not addressed.
