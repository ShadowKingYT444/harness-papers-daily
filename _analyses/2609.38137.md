## One line
A benchmark of four long-context tasks that separates harnesses on *both* accuracy and compute cost, showing that no harness wins everywhere and that extra inference often buys nothing.

## The problem
Existing long-context benchmarks (LongBench-v2, OOLONG-Synth, HELMET) saturate on accuracy: strong model-harness combinations all score similarly, so you can't tell which harness strategy is actually better. Worse, accuracy alone hides order-of-magnitude cost differences — two systems can reach similar accuracy while one spends 12x more compute. The authors argue long-context harnesses must be evaluated as model–harness *combinations* on an accuracy–cost frontier, using tasks that admit multiple solution strategies with genuinely different costs.

## How it works
Four tasks, each with ~100–120K tokens of information-dense context and exact-set scoring, designed so that retrieval and reasoning are coupled (intermediate findings determine what to retrieve next):
1. **Constraint Solving Search**: ~160 people described across documents; find all five satisfying 3–5 scattered conditions (e.g., works nights, uses transit, eats fruit). One condition is deliberately selective and one common, so checking the selective condition first is far cheaper than checking everything for everyone.
2. **Equivalent Program Pair Search**: 200 Python programs (from APPS, statements and I/O examples stripped); find every functionally-equivalent pair hidden among behaviorally-different near-mutant lookalikes. Requires grouping by inferred purpose, then pruning with distinguishing inputs.
3. **Program Execution Tracing**: recover an 8-step query program from 320 shuffled records of prior computations; earlier outputs become the search keys for later steps, so a wrong match corrupts the whole trace.
4. **Outlier Memo Detection**: 700 memos with 2,500 statements; find the 15 memos containing claims that contradict relationships established only by combining facts from *other* memos.
Each instance gets a 3M-token budget (cumulative input+output). They evaluate five models (GPT-5.6-sol, Gemini 3.8 Flash, Qwen3.8-27B, GLM-5.3, Kimi-K2.6) under direct inference and four harnesses (RLM, OpenCode, mini-swe-agent, ReAct), reporting exact accuracy plus estimated USD cost per instance.

## Key results
- The benchmark stays hard: the best configuration (GPT-5.6-sol + mini-swe-agent) reaches only 68% macro-average accuracy; Kimi-K2.6 never exceeds 1.5%.
- Same accuracy, wildly different cost: on Outlier Memo Detection, RLM hits 92% at $7.23/instance while mini-swe-agent hits 100% at $0.583 (12.4x cheaper) by collecting facts into a table and verifying with a local script instead of repeated model reads.
- More inference doesn't ensure success: on Equivalent Program Pair Search, GPT-5.6-sol + RLM scores 2% at $7.86 vs 44% at $0.78 for direct inference — RLM's recursive decomposition groups programs well but leaves too many candidates for the final comparison step.
- No harness leads on all four tasks; every harness both helps and hurts GPT-5.6-sol relative to direct inference (e.g., OpenCode lifts Program Tracing 94%→96% but collapses Outlier Memos 44%→10% and Pairs 44%→0%).
- Weaker models gain more from harnesses: Qwen3.8-27B goes 0%→38.5%, GLM-5.3 9.5%→42.5%, nearly matching GPT-5.6-sol's harnessed scores.
- On the two existing benchmarks the same configurations show either uniformly positive gains or weak separation — the new tasks reveal structure the old ones hide.

## How it relates to adaptive decomposition
This is an evaluation benchmark, not an optimizer — nothing here evolves a harness, so the mechanism overlap is zero. Two angles make it worth knowing anyway. First, it's a cautionary data point on decomposition itself: RLM *recursively decomposes* the long prompt into subcalls, and on Equivalent Program Pair Search that decomposition actively hurts (2% at 10x the cost) because it shrinks the context per call without shrinking the final decision space. An adaptive-decomposition system that splits subproblems needs to check that the split actually reduces the remaining work, not just the per-call context. Second, the paper establishes per-instance compute cost as a first-class metric — exactly the currency per-component search budgets would be measured in — and its task design (multiple strategies, different costs, exact verification) is a natural testbed for evaluating an adaptive-decomposition harness against fixed harnesses.

## Limits and open questions
Cost is estimated from API rates, not measured compute, and token prices are a moving target (Appendix C). Only five models and four harnesses are tested, all on English text/code tasks — no tool-use-heavy or multimodal settings. Exact-set scoring is brittle: a run that finds 14 of 15 outlier memos scores the same as one that finds none, which undervalues partial reasoning. The paper compares static harnesses; it says nothing about *evolving* harnesses or whether the observed accuracy–cost tradeoffs are stable across optimization. And the tasks are synthetic by construction — it's an open question whether the harness rankings transfer to real long-context workloads.
