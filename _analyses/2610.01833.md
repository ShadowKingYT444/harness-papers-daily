## One line
In 240 agent trials, process-level checks found additional deviations in 92.6% of runs that already passed the applicable final numerical checks, and dependency attribution reduced an average 6.34 failed checks to 2.65 root causes.

## The problem
A harness can produce the right final number for the wrong reason. If an evolving system is selected only by terminal reward, it can silently drift in tool choice, arguments, execution order, or state changes while still passing the visible outcome check.

## How it works
The framework independently computes per-run ground truth and materializes reusable runtime-resolved template tests. It combines outcome checks with process checks for tool selection, tool arguments, execution order, and database integrity. Most checks are programmatic; a narrowly scoped LLM judge is used where deterministic checks are not enough. The study covers 240 trials across two skills, two specification variants, two harnesses, and three models. A dependency-attribution step groups downstream failed checks under smaller sets of root failures.

## Key results
Of 175 trials that passed all applicable final numerical checks, 162, or 92.6%, still had another evaluator-detected deviation. Under a broader seven-check final-state definition, 151 of 164 passing runs, or 92.1%, still violated a trajectory check. Dependency attribution reduced the mean number of failed checks from 6.34 per run to 2.65 root causes.

## How it relates to adaptive decomposition
This maps directly onto RHEvolution's evaluator artifact. The optimizer needs more than a scalar pass/fail score: it needs evidence about where the trajectory diverged and which failure was upstream. Process checks provide local evidence; dependency attribution turns many symptoms into a smaller root-cause set. That can feed the ownership graph used for split, fuse, or edit proposals.

## Limits and open questions
The evaluation is on one enterprise system with two related skills, and longitudinal validation under real API evolution is still future work. Process-level tests can also overconstrain an agent if they encode one preferred procedure when multiple procedures are valid.
