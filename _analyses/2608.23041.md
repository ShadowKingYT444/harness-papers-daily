## One line
An offline harness-optimization loop that diagnoses failed agent trajectories, generates structured code-level patches to prompts/tools/middleware, and keeps only updates that generalize on a dev set.

## The problem
Manual harness tuning is slow and expensive: you have to search a big space of prompts, tool configs, and runtime control logic, and every candidate needs costly multi-step rollouts to evaluate. Existing automatic harness optimizers (Meta-Harness, GEPA) either reflect shallowly on failures or edit the harness without restraint, so their updates don't stick across new tasks. AutoSaddler wants harness updates that are *durable* — fixes that survive contact with unseen tasks.

## How it works
Each iteration runs the current harness on a mini-batch of training tasks, then enters a **Diagnosis–Patch session**: a Diagnosis-Patch Agent gets the failed execution traces *and* the harness source code, progressively retrieves relevant trace details (to dodge long-context problems), forms root-cause hypotheses, and writes a **structured patch** Δθ. Patches are restricted to a fixed taxonomy of 3 categories × subtypes: Prompt patches (rule addition/modification), Tool patches (new tool, argument modification, implementation fix, description fix), and Middleware patches (pre-tool-use hooks, infra changes, agent-loop logic changes). Each subtype is labeled a **Capability patch** (changes code/orchestration) or a **Steering patch** (text-only edits like prompt reminders), and a phased schedule does capability patches first, steering patches later — like a learning-rate schedule. The patched harness is verified on the same mini-batch, then a **Reflection session** compares before/after traces (fixed / regressed / still-failing / still-passing) and writes lessons into **EvoDAG**, a directed acyclic graph of the optimization history where nodes are past harnesses and edges are the diffs between them. An **Evolution agent** then synthesizes the next harness by recombining elements from *any* prior nodes in EvoDAG (evolutionary merge across lineages, not just the latest), aiming to escape local optima. After the rollout budget is exhausted, the candidate with the best dev-set score is selected and tested once on held-out data.

## Key results
On GAIA2, SWE-Bench Pro, and Terminal-Bench 2.0, AutoSaddler beats the base harness by 9.0, 9.6, and 10.0 percentage points respectively, and beats the strongest automated baseline by 7.4, 4.4, and 6.7 points. On GAIA2 it reaches 72.3% dev accuracy with ~1,000 total task executions vs ~2,800 for GEPA/Meta-Harness, and needs only 147 traces (~10× fewer than Meta-Harness's 1,400) to reach its best score. Ablations support three ingredients: deep debugging over shallow reflection, targeted modifications over unconstrained editing, and generalization-aware selection over trajectory-specific repair. (Source: full paper, pages 1–6.)

## How it relates to adaptive decomposition
AutoSaddler is a direct comparison point: it optimizes the whole harness as code, exactly the class of recursive/self-improvement work adaptive decomposition sits in. But the differences are the interesting part. Its decomposition of the harness is **fixed and human-designed** — the search space is θ = (prompts, tools, middleware) and the mutation catalogue is a fixed taxonomy (Table 1's subtypes). The agent never *discovers* a new decomposition; it picks among pre-defined patch types. There is no splitting of the problem into subproblems with independent budgets, no parallel component evolution, no split-further-on-failure or fusion of working pieces, and no monolithic fallback. Evolution here is recombination of whole-harness lineages in EvoDAG, not hierarchical decomposition of the search surface. So: same "harness as code" search object as adaptive decomposition, but a fixed, flat mutation grammar instead of an evolvable decomposition hierarchy.

## Limits and open questions
The patch taxonomy is hand-crafted — if the optimal fix doesn't fit one of the ~10 subtypes, the agent can't express it. Diagnosis quality bounds everything: if the agent misdiagnoses a long-horizon failure, the patch is wrong and EvoDAG just memorizes the mistake. The fixed capability-then-steering schedule is a heuristic, not learned. Also, the paper deliberately excludes memory/skill components (assumes stateless tasks), so it's unclear the method transfers to agents whose state persists across tasks — which is exactly where adaptive decomposition would have the most to say.
