## What is actually new

VISTA shows that an agent harness can improve reasoning by **preserving raw evidence instead of summarizing it away**.

For interactive visual tasks, the harness stores original frames outside the text context. The model can later retrieve a frame, zoom a region, or inspect pixels when it needs evidence. Text history can still be compacted because the visual source remains lossless.

The core novelty is an **external, queryable observation memory** rather than a bigger prompt.

## Mental model

A visual agent sees a game board 20 steps ago. A text summary says:
"there was a red object near the top."

Later it needs:
- exact object shape;
- relative position;
- whether a small icon changed.

That detail is gone.

VISTA instead stores the original frame. The model keeps only a reference in working context and actively retrieves the old evidence when needed.

This changes context management from "compress everything" to "compress references, preserve sources."

## Key objects and state

- **Lossless visual archive:** original screenshots/frames.
- **Frame IDs / timestamps**
- **Active inspection tools:** retrieve, crop, zoom, read region.
- **Text interaction history**
- **Context compaction:** shorten old text.
- **Revisable notes:** small persistent files with current hypotheses/state.
- **Environment action interface**
- **Observation references:** pointers from reasoning to archived evidence.

## Reasoning loop

~~~mermaid
flowchart TD
    A["Environment returns new frame"] --> B["Store full original frame outside context"]
    B --> C["Add compact frame reference to working context"]
    C --> D["Model reasons using current state + notes"]
    D --> E{"Need old visual evidence?"}
    E -- "Yes" --> F["Retrieve old frame / crop / zoom"]
    F --> G["Return requested visual detail"]
    G --> D
    E -- "No" --> H{"Context too long?"}
    H -- "Yes" --> I["Compact text history, keep visual archive unchanged"]
    I --> J["Update revisable notes"]
    H -- "No" --> J
    J --> K["Take environment action"]
    K --> A
~~~

## Step-by-step implementation

1. Save every important visual observation in original form.
2. Give each saved frame a stable ID.
3. Put only a compact reference and recent relevant observations in the language-model context.
4. Expose tools to retrieve a prior frame or crop a region.
5. Let the model decide when inspection is worth the extra call/context.
6. Keep a small notes file with current beliefs, goals, and discovered rules.
7. When text context becomes long, compact old conversation/tool text.
8. Never replace the underlying visual archive with the summary.
9. Log which frames/regions were retrieved before each decision.
10. Measure the marginal value of storage, active inspection, notes, and compaction separately.

## Why active retrieval beats automatic replay

Putting every old screenshot back into context would:
- consume huge multimodal context;
- distract the model;
- repeatedly process irrelevant images.

VISTA separates **storage** from **attention**. Evidence is cheap to retain but only expensive to inspect when the model requests it.

This is analogous to external memory in coding agents: keep raw traces/log files on disk and retrieve the needed region instead of repeatedly summarizing everything into one prompt.

## Experimental evidence

The paper reports large gains on interactive visual reasoning tasks, including ARC-AGI-3-style environments and other visual games.

One BabyVision-style result rises roughly **41.0 → 63.2** with the visual harness.

The complete VISTA system substantially outperforms a minimal harness across several game/interactive evaluations, and component-ladder experiments identify lossless memory plus active inspection as major contributors.

## Important contamination caveat

Some evaluated public games existed before the tested model releases. The paper acknowledges that benchmark contamination cannot be ruled out.

Therefore the cleanest claim is not "the model learned these games from scratch." It is that **given the same model**, preserving and querying raw visual evidence changes interactive performance.

## Why this matters for harness evolution

RHEvolution will depend on traces to assign failure ownership.

If the deployed harness aggressively summarizes:
- terminal output;
- screenshots;
- tool responses;
- intermediate files;

then the optimizer may lose the exact evidence needed to diagnose a failure.

The solver's context policy and the optimizer's evidence store should be different.

You can compact the solver's working context while keeping a complete external trace for diagnosis/replay.

## Failure modes and limits

- Raw visual archives consume storage.
- Retrieval tools can become a new source of mistakes.
- The model can inspect the wrong frame/region.
- Public-game contamination weakens absolute benchmark interpretation.
- Visual games are not the same as real desktop/robot workflows.
- More evidence can still distract if retrieval is poorly controlled.

## Implementation checklist

Separate:
- **working context**: small, current;
- **evidence store**: complete, lossless;
- **persistent notes**: revisable abstractions.

Every compacted observation should keep a pointer to its source.

For RHEvolution traces, preserve:
- raw tool outputs;
- full files/diffs;
- screenshots when relevant;
- timestamps;
- owner/component activation.

## What RHEvolution should take from it

Do **not** let context optimization destroy research evidence.

A RHEvolution candidate can use aggressive masking/compaction for the task solver, but the outer optimizer should retain full traces outside that context.

This also gives a useful design principle:
**summaries are hypotheses; raw traces are evidence.**

Split/fuse decisions should be traceable back to the original evidence, not only to a compressed LLM-written summary.
