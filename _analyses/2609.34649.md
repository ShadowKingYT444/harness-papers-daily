## One line
ContextEvo is a harness-evolution framework that learns a *context policy* — how information is assembled, maintained, and shared across a long-horizon run — from execution trajectories, using failure attribution plus counterfactual replay to decide what to change.

## The problem
Skill/rule-based harness evolution works on short tasks but degrades on long-horizon ones: as interaction histories grow, useful evidence gets buried under redundant or outdated context, so extracted skills are low-quality and get invoked at the wrong time. Meanwhile context management itself (compaction, summarization, subagent handoff design) typically stays fixed while the rest of the harness evolves. The paper asks: can an agent evolve its *context policy* automatically, systematically, and effectively — while the base model stays frozen?

## How it works
A context policy is formalized as P = (P_in, P_hist, P_orch): **Input Assembly** (tool-result formatting, observation compression), **History Maintenance** (compaction, summarization, persistent state), and **Context Orchestration** (subagent instructions, feedback design). Each evolution round runs three stages. (1) **Trajectory evidence reconstruction**: scan full trajectories for information-processing events, then paginated review reconstructs the exact model-visible context at key decision points, carrying a running note across pages so earlier info handling can be linked to later failures. (2) **Failure attribution**: an analysis agent compares successful vs failed trajectories and produces attribution hypotheses h = (b, j, E_h), where b ∈ {missing, degraded, buried, polluted} is the failure type and j ∈ {in, hist, orch} is the policy dimension to fix. When evidence is inconclusive it runs **counterfactual replay**: hold the execution prefix τ_<t fixed, edit only the model-visible context c_t, and sample N next actions under both contexts to test whether the change improves the decision locally. (3) **Constrained policy update**: a policy editor modifies, combines, or introduces mechanisms along the identified dimensions, restricted to a safe update set U_safe(P); if no attribution is supported, the policy is left unchanged. All roles (acting agent, analyst, editor) use the same fixed base model.

## Key results
Starting from the open-source Pi-agent harness, with two evolution iterations on three long-horizon benchmarks: under DeepSeek-V4-Flash, full-benchmark scores iter-1 → iter-2 went 44.8% → 45.3% on Long-Horizon-Terminal-Bench (46 tasks), 69.0% → 71.7% on DeepSWE (113 tasks), and 85.6% → 88.5% on BrowseComp-Plus (174 tasks) — iter-2 beat iter-1 in all six benchmark–model settings, and the evolved policies matched or beat Codex/OpenCode/OpenClaw baselines. Under GPT-5.6-Luna: 31.0% → 34.3%, 11.5% → 14.2%, 39.1% → 42.0%. Head-to-head vs skill evolution on LHTB-46: skill-only evolution *lowered* reward 0.417 → 0.370 while raising tokens 8.57M → 9.61M (only 20 of 44 trajectories ever read a skill body); ContextEvo reached 0.448 with 7.52M tokens, and adding skills on top dropped it to 0.419 with 9.69M. Vs context baselines (static ReSum/ACON, local TACO): ContextEvo best on all three benchmarks. Ablation: removing paginated review cost −12.15 pp; removing counterfactual replay hurt held-out 43.12% → 35.29%. Policies transfer across models within an environment but not across environments (frozen LHTB policy on DeepSWE hurt by up to −7.96 pp). Cross-harness check on BrowseComp-Plus hard174 with GPT-5.6-Luna: OpenCode 35.06% → 40.80%, OpenClaw 18.97% → 45.40%.

## How it relates to adaptive decomposition
No agent-discovered decomposition anywhere in the loop. The three policy dimensions are a fixed human-designed taxonomy; evolution mutates/combines/introduces mechanisms *within* those dimensions, one policy at a time, sequentially — there are no independent search budgets per component, no parallel subproblem evolution, no split-further/fuse operations, and no local-vs-global correctness check with monolithic revert. The "decomposition" of tasks into subtasks (subagent orchestration) is part of what gets optimized, not a structure the agent invents. Where it converges with adaptive decomposition's spirit: the counterfactual replay is a local-vs-global test (does the change improve the decision *here* without derailing later execution), and the ∆=∅ fallback ("if no attribution is supported, change nothing") is a weak revert. But the structure being optimized is evolvable only in *mechanism*, never in *decomposition*.

## Limits and open questions
The paper's own conclusion flags the limit honestly: cross-case evidence supports an attribution and replay measures only local next-action sensitivity — neither establishes a task-level causal reward contribution for an individual policy mechanism. Only two evolution iterations were run (iteration 3+ unknown), the LHTB policy sometimes regressed held-out under Luna (BrowseComp-Plus held-out dropped −1.0 pp at iter-1 before recovering), and evolved policies don't transfer across environments, so each new task family needs its own evolution run. Open probe for adaptive decomposition: would per-component independent budgets plus explicit fuse/revert have found the environment-specific policies faster, or would they have fragmented the shared-context invariants ContextEvo currently keeps whole?
