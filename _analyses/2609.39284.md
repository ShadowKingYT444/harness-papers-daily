## One line
A benchmark for skill-evolution harnesses that finally separates genuine capability abstraction from rote solution memorization, governed by one axiom — "capability overlap without solution overlap": 30 learning tasks distilled into a frozen skill bank, then 13 unseen cross-domain projects driven by an LLM-simulated user. The headline result: static skill banks can't clear the "last mile" of exact implementation (correctness +4.62 pp), but they cut coding time by 55.3% by killing token-heavy trial-and-error.

## The problem
Skill-evolution harnesses (Voyager, ExpeL, AgentCL, the authors' own SkillHone) claim to distill reusable engineering skills from past experience, but their evaluations suffer an identifiability problem the paper formalizes as `Downstream Score = f(Distillation Capability × Presence of Evidence in History)`. Treating the right side as a black box makes the left side unmeasurable: a high score might be zero-shot intuition or copied solutions, a low score might just mean the history lacked the relevant knowledge. The dominant failure mode is **solution leakage** — benchmarks repurpose SWE-bench-style intra-domain task sequences, where agents hit artificially high transfer scores by copying ASTs, local APIs, or database schemas from the same repo's history. Conversely, preventing solution reuse isn't enough: learning and test tasks must still share transferable skill dependencies, or the history is irrelevant. When an agent fails on a new project, existing benchmarks can't tell you whether the memory framework failed to abstract the skill or the benchmark simply provided the wrong history.

## How it works
The paper's answer is the golden axiom: **Capability Overlap Without Solution Overlap**. Concretely:
- **30 learning tasks across 6 business domains** (Resource Booking & Logistics, Data & Collaboration, Transaction & Ledger, IoT & Configuration, Security & Moderation, Infrastructure & Communication), yielding feedback-rich trajectories (583 interactive turns) that include the agent's initial mistakes, test failures, and iterative fixes — not just final correct code. Every task and distilled skill is human-expert validated for feasibility.
- **13 long-horizon transfer projects** sharing zero business logic or APIs with the learning tasks. These are not single-turn tests: an LLM-simulated user drives 25–30 interactive turns per task over multi-hour development cycles, asking follow-ups, checking progress against a frozen plan, and rejecting incomplete drafts. To succeed the agent must dynamically compose abstract skills across domains (many-to-many transfer).
- **Strict two-phase protocol:** Phase 1 distills learning trajectories into a Skill Bank compiled into a manifest with SHA-256 hashes; Phase 2 freezes it. Transfer runs execute in isolated Docker containers with no access to learning workspaces or histories, and skill evolution is disabled during transfer. Hidden evaluators stay unmounted during development; once the public interface checker passes, the commit is frozen and evaluated in a separate container — anti-look-ahead-bias isolation.
- **CCPF metric** (Confirmed-Case Pass Fraction): `P_t / |C_t|` over all applicable hidden cases, equally weighted; self-authored agent tests are ignored, and unresolved states, crashes, or unreached cases stay in the denominator — no credit for partial work. Hidden stress tests cover five dimensions (Contracts & Lifecycle, Data Idempotency & Concurrency, Worker Recovery & Durability, Cross-Layer UI Consistency, Operational Compatibility), with adversarial cases: 64 concurrent same-idempotency-key requests, SIGKILL-then-recover worker checks, and anti-hallucination checks that break dependencies — if the agent's tests still pass under broken conditions, the submission fails.
- **Controlled experiment:** GPT-5.5 Medium as coding agent, DeepSeek V4 Pro (thinking/high) as simulated user, fixed requirements and frozen plan (to isolate execution from planning). Four configs × 4 representative tasks (CapacityLease, EscrowGuard, MeterSettle, FlagFoundry) × 3 trials = 48 audited trajectories. Configs: No Skills; S-Full-20 (368 raw skill packages distilled via a two-stage pipeline into 20 cross-domain skills); S-Ablated-20 (69.66% of historical text removed before the same pipeline — evidence-deprivation test); Coreless-3 (S-Full-20 surgically stripped to 3 basic interface skills — capability-deprivation test).

## Key results
- **The "last mile" bottleneck:** S-Full-20 improves micro-average CCPF by +4.62 pp (46.63% → 51.25%), but unevenly — EscrowGuard jumps +14.81 pp while CapacityLease *regresses* −1.45 pp. The authors' reading: a reusable engineering principle is an architectural compass, not an executable implementation; the last mile of exact code still depends on the base model's reasoning limits, which static skills cannot bypass.
- **The efficiency paradigm:** coding time collapses 55.3% (189.00 → 84.46 min, ~104 min saved per run), non-cached input tokens drop 80.91%, while completed dev turns barely change (−1.85%) — the agent works just as long but stops thrashing. Network wait accounts for only ~6 min of the saving; the rest comes from avoiding catastrophic architectural errors early, slashing redundant context bloat.
- **Capability trumps history volume:** S-Ablated-20, built from 69.66% less raw history, achieves the *highest* CCPF (52.60%) with only +8.6% time penalty vs S-Full-20. Distillation quality, not evidence quantity, carries the transfer. Coreless-3 collapses in the other direction: CCPF 48.36% and time ≥190.87 min — worse than the No Skills baseline — supporting that the abstracted *procedures* (concurrency control, recovery) are what produce the gains.
- **Behavioral audit:** S-Full-20 invokes the patch tool 29.8% less often while total added lines drop only 3.66% — edits grow from ~47 to ~64 lines per patch, i.e. decisive execution over fragmented edit-check loops. Coreless-3 is the thrashing extreme: tool invocations +68.97% and reasoning tokens +131.76% (~700k) vs S-Full-20, with 14.76M characters of error logs and 26 context compactions.

## How it relates to adaptive decomposition
EngramBench does **not** implement adaptive decomposition — and that is the precise tension. It is a measurement instrument for *static* skill banks: the protocol explicitly freezes the bank and disables skill evolution during transfer, so any system that discovers its decomposition online, splits failing components, fuses working ones, or reverts toward monolithic state would be evaluated only in frozen snapshot form. The benchmark's anti-leakage freeze is at odds with evaluating the dynamic, continual side of the mechanism.

Still, it offers things adaptive decomposition directly needs:
- **A decomposition diagnostic, not just a score.** CCPF is requirement-level and per-dimension (idempotency/concurrency vs recovery/durability vs UI consistency), which is exactly the granularity you'd want for split decisions: a component failing dimension B but passing A and D is a candidate for splitting, not for discarding. Pass@1-style metrics can't supply that signal.
- **The last-mile result bounds the mechanism's claim.** Adaptive decomposition argues the right decomposition changes search efficiency; a static bank already delivers a 55.3% time reduction and an 80.91% non-cached-token reduction. That's a lower bound an adaptive version must beat — and the "compass, not implementation" finding warns that no decomposition trick, however clever, removes the base model's reasoning bottleneck at the leaves. Splitting won't fix a component the model simply cannot implement.
- **Content, not count, governs fuse decisions.** The S-Ablated-20 vs Coreless-3 contrast says a fused component's value lives in the specific abstracted procedures it carries, not in skill count or history volume — so fusing working components must preserve those procedures intact, and "has many subcomponents" is not evidence of capability.
- **Many-to-many composition is the bar for dynamic discovery.** The benchmark's tasks require composing skills from different domains (e.g., append-only ledger correction from BillForge composed with fault-injection recovery from QueueForge); an adaptive system evaluated here would have to *discover* that composition online, with no human-designed skill boundaries — precisely the mechanism's claim, and EngramBench is the closest existing instrument that could verify it.

## Limits and open questions
- **Scale:** the deep ablation is 48 trajectories over 4 of the 13 transfer tasks; a single run can consume up to 66 million tokens and requires manual auditing, so the full-suite audit is stated as ongoing work. All conclusions rest on that 4-task subset.
- **Static banks only.** The freeze that makes the benchmark rigorous also means dynamic retrieval (Active RAG), continual online skill updates, and any recursive-decomposition dynamics are deliberately excluded. This is by design, but it limits what the benchmark can say about the systems that matter most.
- **Single-model grounding.** All empirical findings come from one coding agent (GPT-5.5 Medium) and one simulated-user model (DeepSeek V4 Pro). The last-mile bottleneck and the 55.3% figure are statements about that pairing, not about procedural memory in general.
- **The S-Ablated-20 anomaly cuts both ways.** The authors read "69.66% less history, best CCPF" as proof that capability beats volume — but an alternative reading is that the LLM distiller is doing the real abstraction work and is insensitive to evidence deprivation, which would make the benchmark partly a test of the distiller, not of the history. The presence-of-evidence guarantee in their equation (1) is less clean than the axiom suggests.
- **Coreless-3 was exploratory.** It was designed after inspecting the S-Full-20/S-Ablated-20 comparison, not pre-registered — honest, but it weakens the causal reading of the collapse.
