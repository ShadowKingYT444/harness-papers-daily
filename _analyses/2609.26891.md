## One line
JAZ is a minimalist agent framework built on a single LLM primitive, `invoke` — a function whose body is generated by the model at call time — and the paper shows this alone (plus prompting) can beat specialized memory and self-improvement harnesses.

## The problem
Modern agentic capabilities like long-horizon memory and continual self-improvement are usually bolted on as specialized external harnesses layered over the agent loop (e.g. Letta/MemGPT for memory, ACE for self-improvement). The authors ask whether a minimal harness that is "little more than the agent loop itself" can exhibit these capabilities, instead of requiring dedicated engineered systems.

## How it works
The core primitive is `invoke(...)`: syntactically a function call with arbitrary named inputs, semantically a call to an LLM that writes the function's body as code in an augmented language — and since the augmented language contains `invoke` itself, the model can recursively call `invoke` to spawn subagents, making recursive subagents the default rather than a special feature. The second defining property: everything visible to the model — all named inputs (task spec, data, tools) and the REPL interaction history (`__history__`) — are ordinary variables in the code environment, so the agent can programmatically inspect and pass them by reference instead of copying text. Around this, JAZ adds three systems: dynamic scoping (a `scope` context manager that makes variables like tools visible to all recursive sub-invokes), a hook system (observability loggers, resumability via trajectory replay, resource control like `BudgetPool`/`IterationLimit`/`ContextWindowWarning`, validation like `ReturnType`), and a configuration system (`Config(llm, repl, protocol)`) that can be local or dynamically scoped. Two case studies demonstrate the expressivity: for long-horizon recall, the `ContextWindowWarning` hook prompts the agent to do "tail-recursive delegation" — delegating remaining work to a subagent while passing the full history by reference via a `prev_history` variable, so nothing is lost across context windows; for continual self-improvement, the top-level `invoke` acts as a meta-agent that optimizes the solver sub-invoke's prompts and skills across a task sequence based on test feedback.

## Key results
StuLife long-horizon benchmark (939 graded tasks, GPT-5.4 nano): JAZ invoke achieves 72.6±0.1% pass rate overall and 69.9±1.8% on the 207 "far recall" tasks at $18.3±0.3 per run, vs the specialized memory harness Letta at 61.8±2.3% far-recall pass at $42.1±1.6, and CodeAct+subagents at 32.0±2.3% at $13.1±0.9. On one analyzed task, JAZ invoke was at recursion depth 70 after 69 tail-recursive delegations and still retrieved a protocol from 497 tasks earlier because history was passed losslessly by reference. AppWorld test-challenge (continual self-improvement): JAZ invoke reaches 74.2±2.1% TGC and 51.1±3.7% SGC at $20.9±3.7, vs ACE at 69.9±1.4% / 47.1±1.3% at $30.6±0.5, and CodeAct+subagents at 71.1±1.3% / 47.6±2.1% at $21.6±1.8. Means and standard errors over 3 runs (6 for self-improving methods). All numbers are from the paper; no invented claims.

## How it relates to adaptive decomposition
JAZ does not do adaptive decomposition as a search process: there is no population of harness variants, no independent search budgets per component, and no split/fuse operators over an evolving structure. However, it is the closest paper in this batch to the "agent discovers the decomposition" half of the idea — the recursive subagent structure is not fixed by the human; the LLM itself decides at runtime when to spawn sub-invokes and how to partition state across them (e.g. choosing tail-recursive delegation when the context fills). So the decomposition is runtime-discovered by the agent rather than human-designed, but it serves a single task execution, not an optimization loop over harness designs. The continual self-improvement case study is a fixed meta-agent workflow (optimize solver prompts/skills, test, repeat) with no structural evolution.

## Limits and open questions
The self-improvement is prompt/skill-level only — the `invoke` loop itself is never structurally mutated, so it says nothing about evolving the harness architecture. The expressivity argument cuts both ways: with everything as variables and recursion as default, the agent has enormous freedom, and the paper does not study failure modes where the agent delegates pathologically or the meta-agent overfits to the task sequence. Open probe: give JAZ an explicit objective to rewrite its own hooks/configuration (not just prompts) and see whether the minimal loop can discover better harness structures — that would be the bridge from runtime recursion to true adaptive decomposition.
