## What is actually new

MESH-Harness divides a harness into fixed functional slots. Each slot keeps alternative implementations. Full-covariance LinUCB scores complete module combinations from observed validation scores and uncertainty. Mixed-start coordinate ascent selects combinations without exhaustive enumeration. Validation traces then drive local code edits and pool refresh.

The key RHEvolution limitation is that the slot boundaries stay fixed. This makes MESH a strong baseline for testing whether adaptive split, merge, and recomposition add value beyond good fixed-module search.

## Optimization loop

~~~mermaid
flowchart TD
 A["Module pools"] --> B["LinUCB combination score"]
 B --> C["Select full configuration"]
 C --> D["Run validation tasks"]
 D --> E["Score + lossless traces"]
 E --> F["Update surrogate"]
 E --> G["Trace-guided local edit"]
 G --> H["Refresh module pool"]
 H --> A
 F --> A
~~~

## Results that matter

Under a matched 40-candidate evaluation budget, MESH reports gains over Meta-Harness of **+5.70** points on text tasks, **+7.01** on retrieval-augmented math, **+2.00** on LiveCodeBench, and **+5.00** on ScienceWorld. Iterative optimization improves first-round configurations by **5.63-7.79** points.

Reported aggregate test-time cost is **44.2% lower** than Meta-Harness. Total cost including search is **14.6% lower**.

The selection ablation reports 48.80 for random composition, 51.70 for LinUCB without the exploration bonus, and **56.33** for full LinUCB. The pool ablation reports **56.33** for the full method, 51.20 without pool refresh, and 53.80 with refresh but without historical traces.

## Why this matters for RHEvolution

Use MESH as the fixed-decomposition control. Do not attribute gains to adaptive decomposition unless RHEvolution beats a fixed-slot search with the same solver, proposer, task set, rollout budget, and number of evaluated candidates.

A useful hybrid is to use MESH-style bandit search inside the current component graph. Structural split/fuse actions should remain separate and should require ownership evidence or intervention results.

## What RHEvolution should change

1. Add an interaction-aware bandit for candidate component combinations.
2. Keep split/fuse as an explicit structural action, not a side effect of module selection.
3. Run a matched-budget fixed-slot MESH versus adaptive-graph RHEvolution experiment.
