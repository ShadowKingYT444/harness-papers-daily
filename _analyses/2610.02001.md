## Main idea
Mingbird is a hand-designed harness for small local models. Each harness mechanism targets a specific observed failure form, such as context overflow, false completion, repeated tool loops, or execution faults.

## Key concepts
- **Failure form:** A recurring type of agent failure with a recognizable pattern.
- **Prefill budget:** A limit on how much tool and system information is placed in the model context before the task starts.
- **Finish gate:** A check that re-reads the task before accepting a completion claim.
- **Loop detector:** A mechanism that detects repeated tool actions with the same arguments.
- **Invariant:** A rule that must always stay true, such as a context-size limit enforced by tests.

## Design loop
```mermaid
flowchart LR
    A[Observe small-model failure] --> B[Name failure form]
    B --> C[Design one harness mechanism]
    C --> D[Enforce invariant or guard]
    D --> E[Run controlled benchmark]
    E --> F[Measure change]
    F --> A
```

## How it works
The paper defines ten mechanisms. Examples include selective tool loading, completion checks, loop detection, sandboxed execution, and recovery from process or encoding faults.

The important pattern is not the exact list. The design process maps a concrete failure form to one explicit harness mechanism and then measures the full system under controlled conditions.

## Why it matters for RHEvolution
Mingbird is a good picture of what an adaptive decomposition system should **discover automatically**.

If repeated traces show false finishes, RHEvolution should create or strengthen a completion-check component. If context crowding is the dominant problem, it should isolate context management. The human-built failure-form inventory can therefore act as a target behavior for automatic component discovery.

It also shows why invariants matter. A self-evolving harness should protect hard limits with tests instead of relying only on prompts.

## Evidence and limits
- Mingbird performs strongly in the paper's controlled local-agent benchmark.
- Some single-mechanism ablations are noisy, and the authors treat them as directional.
- The benchmark and machine setup are self-built and narrow.
- The component set is human-designed, so the paper does not test automatic structural search.
