## One line
A formal theory of when iterative self-improvement must saturate: refinement is gradient boosting on the residual, a fixed reachable edit set forces strict diminishing returns, and the only escape is expanding what the agent can reach — which is exactly what scaffold (tool/decomposition) rewriting does.

## The problem
Agentic coding loops iteratively generate, critique, and refine code, yet the practice has no rigorous foundation for the central RSI question: when does iterative self-modification run out of room, and is a frozen checkpoint evidence that it has? Auditors who check whether weights are frozen are, the paper argues, checking the wrong thing — the object to audit is the scaffold.

## How it works
The paper reads agentic refinement as **gradient boosting on the residual error**: each agent predicts the residual between the current draft and the target (naturally represented as a git diff), making the loop functional gradient descent. It then locates where deployed loops break boosting's preconditions (patches *compose* instead of standing beside each other to be voted on; worker failures overlap rather than diversify) and turns those breaks into a build spec. The formal core (machine-checked in Lean 4):
- **Theorem 2 (Monotone Improvement under Refinement):** with an improvement property V(Rₜ(z,a*)) ≥ V(z) + ηₜ on a bounded quality metric V ≤ 1, total improvement saturates — Σηₜ ≤ 1 − V(z₀).
- **Proposition 3 (Stationarity Dichotomy):** (i) a fixed ceiling forces ηₜ → 0, strict diminishing returns; (ii) escaping requires the effective hypothesis class to *expand* enough to sustain a uniform edge. Expansion is necessary but not sufficient.
- **Corollary 4 (Frozen-Weight Ceiling):** model a self-improving system as S = (W, C) with frozen weights W and mutable scaffold C. Frozen weights buy an *eventual* ceiling V*(W) but no stationarity along the way, because scaffold rewriting expands the reachable edit class Hₜ(C) without touching a weight. Escaping the ceiling requires raising V*(W) itself — modifying weights or architecture.
- **Proposition 5 (Orchestration):** best-of-k selection attains maxᵢ V*(W,Cᵢ) exactly — width buys rate, not budget.
- **Proposition 6:** a majority vote has zero training error iff the tight failure overlap m* < k/2 — a single countable integer decides whether voting is viable.
- **Proposition 7:** re-consulting a fixed worker pool has a finite, computable horizon log(1/ε₀)/2γ² unless the pool can already fit the work.
Three measurement parts: (A) stylized validation on synthetic data (appendix); (B) a real coding agent (mini-swe-agent) as weak learner over 55 SWE-bench Lite tasks × 5 seeds × 4 rounds (1,650 trajectories), crossing model tier with feedback mode; (C) 401 production agentic-coding sessions at an enterprise company, with structural git metrics only, plus a 9,395-session pre-AI human baseline.

## Key results
- Part B: model tier explains roughly half the variance (partial η² = 0.497, p < 0.0001); feedback mode (independent/blind/diagnostic) is null but underpowered, not evidence of no effect. Solve rates: Haiku 44–49% vs Sonnet 85–89% at the τ=0.6 criterion (71–75% vs 29–38% at strict τ=1.0).
- Saturation measured, not argued: mean per-round improvement on the running best decays 0.097 → 0.036 → 0.033 (Haiku) and 0.156 → 0.068 → 0.029 (Sonnet). Loops mostly abstain: ties at 80–95% of transitions, with at most 2.9% of transitions lowering quality.
- Sideways ceiling: on 30 same-family workers, failure overlap sits at its maximum (m* = k), and a majority fails 23/55 (42%) of tasks — exactly the vote's error (0.418, 95% CI [0.291, 0.545]).
- Part C: 70% of multi-commit sessions show decreasing churn, median late/early churn ratio 0.49 (95% CI [0.400, 0.793]) — the signature of the bounded regime in real production. But the pre-AI human baseline shows the same geometric decay shape (ρ_human = 0.86 vs AI ρ ≈ 0.77), so front-loaded editing isn't AI-specific and a fixed reachable class isn't needed to explain it; the authors flag this honestly as a descriptive result without a mechanism.
- Practitioner lessons: spend on the first attempt rather than the refinement loop; reach for capability before orchestration.
- Four falsifiable open problems, notably: (1) build the harness with retention, explicit reweighting of specifications, and enforced m* < k/2, and check whether it descends at the transferred boosting rate; (4) hold weights fixed and vary the scaffold to separate a genuinely fixed reachable class from the ordinary economics of editing.

## How it relates to adaptive decomposition
This is the formal scaffold the user's mechanism has been missing. Adaptive decomposition — an agent discovering the harness decomposition itself, splitting failing components, fusing working ones — is precisely an instance of the expansion move the dichotomy names: it grows the reachable edit class Hₜ(C) without touching weights (assumption M1), which is the *necessary* condition for escaping saturation. Corollary 4 tells you exactly why PluginRSI-style fixed-decomposition evolution must eventually plateau (the edit set is fixed) while an adaptive-decomposition search has a theoretical escape hatch. Two cautions from the same paper: expansion is necessary but **not sufficient** — you need a *sustained uniform edge* under the expanded class, which is the empirical bar an adaptive-decomposition paper must clear (the authors' open problem 3: "keep refining after the first pass" applies directly). And Prop. 6's vote condition plus open problem 2 (cross-family diversity) warn that fusing or voting over independently-evolved components only helps with genuine diversity — same-family components will share hard points, so a naive fuse of subproblem solutions inherits correlated failures. This paper belongs in the related-work section of any adaptive-decomposition publication as the theoretical grounding.

## Limits and open questions
The theory is deliberately criterion-level, not a convergence rate, and rests on modeling assumptions no proof discharges — a bounded quality scale V ≤ 1 (which a genuinely open-ended objective would deny), and class expandability (M1) plus the ultimate ceiling (M2) in Corollary 4. The authors are explicit that the criterion over-flags by construction. Part B is one vendor's two tiers, one harness, one benchmark, four rounds; Part C's model-tier discriminator returned a null the authors attribute to a bad proxy (survivor ratio) rather than to no capability effect. The vote-overlap pessimism is explicitly the "pessimistic half" — low-temperature resampling of one vendor; whether genuinely different model families clear the bar is unmeasured. The prescribed harness (retention + reweighting + enforced diversity) is unbuilt — including by the authors.
