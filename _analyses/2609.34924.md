## What is actually new

This paper gives a theoretical reason that recursive improvement with a **fixed edit space must eventually stall**.

If performance is bounded and every refinement stays inside the same reachable class of changes, the remaining useful gain shrinks toward zero. Continued improvement requires changing the scaffold so the system can reach edits it could not express before.

For RHEvolution, this is the clean theoretical motivation for adaptive decomposition: a split does not only make bookkeeping nicer. It can **change the search space**.

## Mental model

Suppose an optimizer can only edit one prompt. It improves that prompt for 30 rounds. Even if every accepted edit helps, there is only so much performance available inside "possible versions of this prompt."

Eventually the residual failures require:
- a new tool;
- persistent state;
- a different interaction loop;
- a specialist;
- a new verifier.

More prompt iterations cannot express those mechanisms.

The paper calls this a stationarity problem. A checkpoint can stop changing because the **scaffold's reachable edit class** is exhausted, not because the underlying model has reached some universal capability ceiling.

## Key concepts

- **Residual error:** remaining failure after the current solution.
- **Reachable edit class:** all changes the current scaffold/optimizer can produce.
- **Stationarity:** later rounds produce negligible expected improvement.
- **Scaffold:** prompts, tools, memory, orchestration, evaluators, and other external structure.
- **Uniform edge:** an assumption that the search procedure retains some useful advantage over random/noisy change.
- **Correlated workers:** parallel agents that tend to fail on the same hard cases.

## Core argument

~~~mermaid
flowchart TD
    A["Current solution"] --> B["Measure residual failures"]
    B --> C["Search inside current edit class"]
    C --> D["Accept useful refinement"]
    D --> E["Residual error becomes smaller"]
    E --> F{"Marginal gain still meaningful?"}
    F -- "Yes" --> B
    F -- "No" --> G["Fixed edit class is near stationarity"]
    G --> H["Expand scaffold / create new edit targets"]
    H --> I["New reachable edit class"]
    I --> B
~~~

## Why marginal gains must shrink

The intuition is simple.

1. Task quality has an upper bound.
2. If accepted updates keep increasing quality, the total future improvement is finite.
3. A finite total gain cannot contain an infinite sequence of large positive steps.
4. Therefore the gain per refinement must eventually approach zero.

This does **not** mean useful improvement is impossible after that point. It means improvement cannot continue indefinitely under the same restricted class of edits.

Changing the scaffold can create a new class. For example, adding a tool changes which actions are possible; splitting one controller into two specialists changes which policies are representable.

## What the theory does not say

It does not prove:
- that every larger scaffold is better;
- that recursive splitting always creates useful capacity;
- that search will find the good part of the expanded space;
- a specific convergence rate for RHEvolution.

Expansion also increases noise and search complexity. A bad split can make optimization harder.

The theory supports **conditional expansion when the current class is exhausted**, not endless growth.

## Parallelism result

The paper also studies parallel workers/voting.

Adding more workers can improve search when their errors are sufficiently independent. But similar agents often fail on the same hard cases. Correlated errors limit the benefit of majority voting or Best-of-N.

This matters for harness search: running five nearly identical optimizer agents is not equivalent to exploring five distinct structural hypotheses.

## Experimental evidence

The coding-agent experiments show:
- diminishing gains across repeated refinement rounds;
- significant overlap in failure sets across similar parallel workers.

These results are consistent with the theoretical story but do not uniquely prove it. Many practical factors can also cause plateaus.

## Implementation use

Treat stationarity as a measurable trigger.

For one component, track:
- recent accepted gain per evaluation dollar;
- number of distinct hypotheses tried;
- repeated failure clusters that remain unresolved;
- whether successful edits are becoming smaller cosmetic changes;
- whether other components are consistently co-implicated.

When marginal gain falls and unresolved failures remain coherent, consider changing the structure instead of spending more edits inside the old owner.

## Failure modes and limits

- The theory uses simplifying assumptions about bounded quality and improvement.
- Real search has negative steps, noisy measurement, and non-stationary tasks.
- Expanding the edit space can worsen sample efficiency.
- Correlation between agents depends heavily on prompts/models/tasks.
- The paper does not provide an adaptive split/fuse algorithm.

## Implementation checklist for a stationarity trigger

For each owner maintain:
- rolling mean candidate-parent delta;
- confidence interval / evaluation noise;
- budget consumed;
- count of unique failure clusters;
- count of accepted structural versus cosmetic edits;
- coupling with neighboring owners.

Only trigger structural expansion when the plateau is larger than expected evaluation noise and there is unresolved evidence that the current owner mixes separable mechanisms.

## What RHEvolution should take from it

This paper supplies the theoretical "why" for recursive decomposition.

RHEvolution's claim should be more specific than "decomposition improves credit assignment." The deeper claim is:

> **Adaptive decomposition can change the reachable harness search space when a fixed decomposition becomes stationary.**

Test that directly:
1. measure plateau under fixed dimensions;
2. allow a split;
3. show new types of edits become reachable;
4. show held-out/OOD gain resumes;
5. charge the split for added complexity.

If performance does not resume after the split, then the structural expansion was not useful.
