## One line
Searches over full Python harness code with an agentic proposer (Claude Code) that jointly optimizes three objectives — accuracy, behavioral safety, and token cost — instead of accuracy alone.

## The problem
Harness search has been single-objective: prompt optimizers tune prompts within a fixed skeleton, and the one full-harness-rewriting system (Meta-Harness) optimizes accuracy only. Real deployments care about three things at once: a harness that answers right but complies with unsafe requests is bad; one that answers right at 10× the tokens is bad too. And staged approaches (optimize accuracy first, then bolt on efficiency) freeze structural choices early, so the search can never discover cost-aware structures.

## How it works
Meta-Harness runs an iterative propose-evaluate-log loop where the proposer is Claude Code with full filesystem access to prior harness source, per-example scores, and execution traces (~82 files inspected per iteration). The method:
- A harness is a Python class wrapping an LLM client (init + run). The per-domain proposer prompt is composed from three markdown skill files: a base skill (objectives, rules), a domain skill (strategy library like draft-verify, verification cascades, normalization recipes, failure modes), and a safety skill (import whitelists at strict/minimal/light risk levels).
- Each iteration: the proposer applies **one structural mutation from a fixed action set** declared in the skills (rewrite prompt, add/remove verification or retry loop, change model routing, prune context), the candidate clears gates — AST-GUARD static analysis (banned imports/calls/attributes), mock-run validation, a budgeted screening evaluation — and is adopted only on strict improvement of the joint reward.
- MoMHa's headline variant exposes all three objectives in a single phase with scalarized reward R = accuracy + λs·safety − λt·tokens, while the proposer still sees the three raw per-example axes so it knows *which* axis an edit moves. The key mechanism: token optimization is *emergent* — the skill instructs the proposer to find the 20%-of-examples-consuming-80%-of-budget, identify the dominant LLM call in traces, and do a targeted structural rewrite (e.g., skip verification when draft confidence is high), which discovers structures like a single confidence-gated verifier that a two-phase pipeline can't reach.
- Safety is enforced by a 3-layer stack: AST-GUARD, domain safety skills, sandbox execution (30s timeout, 100K tokens, 200 API calls).

## Key results
- Synthetic track: joint mean J=0.482 vs 0.198–0.422 for ten baselines (next best TextGrad 0.422), winning 7/10 domains.
- Real-world track (7 public benchmarks, harnesses transferred from the synthetic track, zero search cost): J=0.461 vs 0.377 for DSPy, winning 5/7.
- Safety: U-SafeBench behavioral composite 0.781 vs 0.569 for Meta-Harness; no baseline clears 0.75. Tokens: 95 fewer per example than the two-phase ablation at higher accuracy.
- Central empirical finding: single-phase joint search beats two-phase accuracy-then-tokens by +2.7 points; trace-level feedback beats scalar scores (0.611→0.604 without it).

## How it relates to adaptive decomposition
MoMHa does **not** decompose the harness at all — the inspected main text shows a single structural mutation per iteration applied to the whole harness from a fixed action catalogue in skill files, with no recursion into components. Its contribution is orthogonal: *what* gets optimized together (three objectives in one phase) rather than *how* the search space is structured. The closest thing to adaptive structure is its per-domain skill composition (different strategy libraries per domain) and confidence-gated verification — but these are human-authored skill content, not agent-discovered decomposition. For adaptive decomposition's positioning, MoMHa is the canonical "fixed action set on a monolithic object" baseline to contrast against.

## Limits and open questions
One mutation per iteration on full harness code is sample-expensive: ~100 harness evaluations per domain and the proposer reads ~82 files per iteration (the paper defers the API-cost comparison). The synthetic domains have only 50 search / 50 test examples, so results are noisy and possibly overfit to tiny splits. The 3D hypervolume framing is nice but the scalarization weights (λs, λt) are themselves design choices that shape what "optimal" means. I'd probe whether the joint-reward win holds with a different proposer model or larger search sets, and whether AST-GUARD's banned lists block legitimate harness patterns.
