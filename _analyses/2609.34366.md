## One line
A competition system report for the DocSem document-reasoning shared task, showing a small model + good harness matching a 72B model — then the same system collapsing on the real test set because the PDFs were watermarked rasters the pipeline couldn't read.

## The problem
Two questions the authors wanted to answer from their DocSem entry: (1) can application architecture (harness) move metrics more than model scale, and (2) why did a system that scored 0.901 joint accuracy on held-out data fall to 13.58% (rank 149 of 163) on the test set?

## How it works
The pipeline (built on RAGU, a graph retrieval toolkit): a PDF goes through hybrid block retrieval to find the quantitative passage, then Program-of-Thoughts generation — the model writes a *program* that a sandboxed interpreter executes — plus self-consistency sampling, and entity enrichment from chunk-level knowledge graphs built by a 7B extractor. The authors interpret the results through a "world knowledge vs. language knowledge" split: world knowledge scales steeply with parameters, language knowledge (comprehension, extraction, faithful reformatting) scales gently, so a harness that offloads arithmetic and retrieval to tools leaves the model only the linguistic residue where a small model is competitive. The second half of the paper is a failure autopsy: the test PDFs were rasterized and watermarked, so OCR quality — not reasoning — separated the leaderboard, which they demonstrate by controlled re-rendering of the validation set.

## Key results
On labeled data: switching a 7B model from direct answering to Program-of-Thoughts added 0.282 joint accuracy, while the same switch moved a 72B model by at most 0.005. A 27B model with the full harness matched the 72B answering directly (0.884 vs. 0.873 joint) at ~2.7× fewer parameters and a quarter of the CO₂ (0.14 vs. 0.53 kgCO₂e). Graph-entity enrichment helped only in distilled form and only at scale (+0.017 on the 27B line) — it *hurt* the 7B line (0.641 → 0.011). On the test set: the same system collapsed to 13.58% joint accuracy, rank 149 of 163; their simulation reproduces the OCR half of the collapse, bounding what simulation misses. (Source: full paper, pages 1–4.)

## How it relates to adaptive decomposition
Barely at all — this is a fixed, human-designed pipeline with no optimization loop and no decomposition beyond a standard retrieve→generate→verify staging. The one relevant nugget is the model-dependence finding: the same harness that rescues a domain-adapted 7B model *taxes* the base model's citation discipline, reappearing across every rigid output format tested. That's a data point for any harness optimizer: component fitness is model-dependent, so an evolvable decomposition can't treat "good component" as a fixed property — a lesson adaptive decomposition's per-component budgets would need to internalize.

## Limits and open questions
Single task, single domain (document QA), and the headline result is confounded by a distribution shift the authors themselves diagnose — the "harness beats scale" claim only holds on clean born-digital PDFs. The world-knowledge/language-knowledge distinction is a post-hoc interpretive frame, not a measured quantity. Nothing here generalizes to harness optimization methods; the failure autopsy (audit your physical inputs before your architecture) is the more transferable lesson.
