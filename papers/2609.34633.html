GenMem: Generative Symbolic Memory for Self-Evolving Harness

Day 23 · Oct 22, 2026

GenMem: Generative Symbolic Memory for Self-Evolving Harness

Xinke Jiang, Tao Feng, Weixuan Xu, Zhixin Zhang, Zhibang Yang, Wentao Zhang, Runchuan Zhu, Xu Chu, Junfeng Zhao, Yasha Wang · published 2026-09-28 · arXiv:2609.34633

relevant

One line

GenMem replaces dense-retrieval memory with generative symbolic addressing: memory agents learn to emit hierarchical discrete address tokens (SIDs) whose slots stay stable while the stored experience payloads are continually revised, letting a memory bank self-evolve without addressing drift.

The problem

Self-evolving agents need long-term experience memory, but dense retrieval couples addressing to content: every time an experience is revised, its embedding changes and silently reroutes which queries reach it — "address variance." Reusable experience is also sparse and hierarchical (most entries redundant, refinement concentrated on repeatedly exercised entries, sub-skills shared across tasks), and its only supervision is delayed, indirect task-level feedback. The paper asks how an agent can keep learning "which functional experience to fetch" rather than a mapping to content versions that go stale with every revision.

How it works

Each memory entry is (x_i, z_i): a text payload x_i and a Symbolic Identifier z_i = (s_1, ..., s_L) in a Cartesian product [N_1]×...×[N_L]. SIDs are built offline: an LLM distills successful/failed trajectories into reusable procedures (seed set), a frozen encoder embeds them, and RQ-KMeans fits hierarchical codebooks to residuals — level 1 clusters embeddings, level ℓ+1 clusters the residuals. With codebook sizes (48,16,8,8) this yields 49,152 addresses from 80 discrete tokens. Codebooks are frozen after construction. The core invariant: evolution rewrites the payload in place, Evolve: (x_i, z_i) → (x′_i, z_i); the address never changes, so revision is decoupled from addressing.

Three agents form a closed loop. MemRetriever generates a retrieval SID z_r from the query/context, fetches the payload, and rewrites it into task-adaptive support. StackPlanner (a multi-agent harness) executes the task, producing an answer and trajectory. MemEvolver distills the trajectory, generates an update SID z_e (not recomputed from the new payload), and returns an operation o ∈ {insert, revise} with a new payload — revise supports retention (unchanged), consolidation (merged), or deletion (empty payload). Training is four-stage: (1) SID alignment pretraining — five text↔SID mappings (q→z, τ→z, x→z, z→x, z→d) with an autoregressive next-symbol loss; (2) memory-operation mid-training — ReAct-style trajectories with rejection sampling and teacher distillation; (3) joint GRPO post-training (130 steps) with a dense process reward R_process = R_format + R_strategy + R_SID plus a contrastive outcome reward R_out = r_task(memory) − r_task(no-memory) + partial credit; (4) online self-evolution with all model parameters, encoder, and codebooks frozen — adaptation happens entirely through external memory writes. Emergent finding: SIDs behave like natural-language tokens and are compositional — combining multiple SIDs composes their stored experiences (one case shows "address decomposition" C → A+B, retrieving complementary sub-skills instead of copying one entry).

Key results

Offline evaluation (RQ1) spans ALFWorld, WebShop, search-augmented QA (2Wiki/HotpotQA in-domain; Bamboogle, MuSiQue, NQ, TriviaQA out-of-domain), plus medical reasoning and deep research, against memory-augmented baselines and RL methods. GenMem averages +17.0 percentage points before and +15.3 pp after Harness-RL training of StackPlanner versus memory-free baselines, and beats the second-best method SDAR by 3.7 pp on average token F1. Retrieval: final Top-5 hit rate 13.15% vs 10.28% (SkillRouter), 12.52% (TF-IDF), 2.89% (Qwen3-Embedding-0.6B). Cross-harness/domain transfer: +2% on Research benchmarks across StackPlanner, TCRAG, and OpenHands harnesses; Search ranges −1% to +1%. Online self-evolution (RQ2) on a held-out stream with frozen models: Candidate Hit rises 20.25% → 25.58% and Task ACC 30.56% → 36.20% from t=0 to t=9, while three content-coupled baselines (which rebuild dense indices each checkpoint) show limited gains or degradation from embedding drift — the paper's empirical confirmation of addressing invariance. Training used 8× A100 80GB GPUs with DeepSpeed ZeRO-3, vLLM rollouts, pretraining LRs 1e-5 and 2e-6.

How it relates to adaptive decomposition

GenMem has the closest-to-evolvable structure of the harness papers here, but its decomposition is on the memory side, not the problem side. MemEvolver autonomously chooses insert/revise with retention, consolidation, and deletion — consolidation is the memory analogue of "fusing working components" — and it targets update addresses itself. But the address hierarchy is fixed by human-chosen RQ-KMeans codebooks: the agent never discovers its own decomposition, never allocates independent search budgets to subproblems, never splits a failing component into finer pieces or reverts to a monolithic state. The symbolic composition/decomposition cases in §5 are post-hoc judged demonstrations of SID compositionality, not a runtime mechanism for discovering problem structure. Fixed action set of memory operations, learned policy for when to apply them, but a human-designed, frozen decomposition.

Limits and open questions

Two limitations the authors admit: leaf codebooks attract disproportionate traffic (uneven utilization), and cold-start noise in early trajectories propagates into the SID space — suggesting adaptive codebook reallocation and background revisit policies. Online evolution is scored against reference answers (never shown to the updater, but still requiring ground truth at stream time), which limits deployment to verifiable domains. The address space is frozen: as genuinely new task families arrive, no new top-level symbols can be born, so capacity is bounded by the offline codebook choice. Next probe: test compositionality at scale — is SID composition reliable beyond the qualitative cases, and can SIDs actually serve as first-class orchestration tokens in long multi-tool workflows, as the authors speculate? Also probe whether a frozen addressing scheme degrades over very long streams where functional regions shift meaning.
