Mingbird: A Local-First Agent Harness Enabling Small Open Models to Complete Real Tasks

Day 75 · Dec 13, 2026

Mingbird: A Local-First Agent Harness Enabling Small Open Models to Complete Real Tasks

Hao Wang, Ting Huang · published 2026-10-01 · arXiv:2610.02001

highly relevant

One line

Mingbird is a hand-engineered local-first agent harness (Windows + Ollama) whose ten mechanisms compensate point-by-point for small-model (2–9B) failure forms — byte-level net-zero prefill budget, a finish gate that re-reads the task before accepting completion, signature-level loop detection — reaching 0.886 on the controlled LRAB comparison vs. 0.631 (goose), 0.479 (opencode), 0.405 (agent-mini), with all 288 cells published.

The problem

Small open-weight models run on ordinary laptops, but under cloud-scale agent harnesses they rarely complete real tasks: tool prefill overflows the context, self-correction diverges, tool demonstrations loop, and tasks are silently abandoned. The paper's claim, backed by a controlled single-machine comparison, is that a substantial share of these failures is attributable to the harness, not the model — so the fix is harness engineering, not bigger weights.

How it works

Mingbird (open source at github.com/Mingbird/Mingbird-agent) decomposes the small-model harness at the mechanism level: ten mechanisms M1–M10, each documented as failure form → mechanism → design rationale with measured per-mechanism costs. Representative ones: a byte-level net-zero prefill budget enforced in CI (M1, with a task-domain router that loads only the needed tool definitions), a finish gate that re-reads the task text before accepting any completion claim (M3), signature-level loop detection over tool name plus arguments with a tiered escalation ladder (M4, extending OpenHands' StuckDetector paradigm), a sandboxed executor with edit safety (M6), and a resilience layer absorbing encoding faults/empty turns/process kills via checkpoints (M7). Evaluation is LRAB — a controlled comparison holding machine, models, budgets, and scoring fixed (4 harnesses × 4 open models 2B–35B × 18 real tasks, deterministic artifact scoring) — plus τ²-bench (278 tasks) and a frontier-model probe.

Key results

LRAB: Mingbird 0.886 overall vs. 0.631 (goose), 0.479 (opencode), 0.405 (agent-mini). τ²-bench: 0.856 vs. 0.791 and 0.737. A frontier-model probe on the same 18 tasks spans 0.997 to 0.478 across harnesses — well-formed scaffolds stay within 0.072 of each other, i.e. the harness dominates the outcome more than the model does at the margin. Leave-one-mechanism-out ablations are reported as directional only (same-night replications move means by up to 0.069, the size of every nominal single-trial delta): removing the finish gate reduces the total by 0.098; the batch-matched comparison of the full stack vs. text re-read alone gives the executable completion guards a paired +0.10.

How it relates to adaptive decomposition

Mingbird is the "before" picture drawn with unusual honesty — a hand-designed, mechanism-level decomposition where every component exists because it fixes a measured failure form. Two things matter for the user's work. First, the failure-form → mechanism inventory is exactly the kind of discovered structure adaptive decomposition should output, not take as input: prefill crowding, false finishes, loops are the decomposition the agent should discover by watching small models fail. Second, the paper is explicit that its mechanism set is hand-designed rather than searched — which is the gap the user's mechanism fills. The cautionary note: Mingbird's per-mechanism deltas are mostly directional (their own ablations admit the noise floor), so the "each mechanism gates a real failure mode" claim is softer than presented — an agent-discovered decomposition with proper statistical validation would be strictly more honest. Also worth stealing: the CI-enforced invariant discipline (byte-level prefill budget enforced by tests) is a concrete version of the invariant-preserving edit discipline an evolving harness needs.

Limits and open questions

The authors state the limits themselves: a self-built benchmark (LRAB), a single machine, single-trial scoring — the ablations are directional only, by their own accounting. The frontier-model probe spans 0.997 to 0.478 across harnesses but is a single probe on 18 tasks. The mechanism inventory is Windows/Ollama-specific in places (MCP injection, sandbox model) and the 2–9B tier focus means the failure forms may not transfer to frontier models. No comparison against automatically-searched harness structures (ADAS/AFlow/DSPy are cited but not benchmarked), so "hand-designed beats searched" is untested here.
