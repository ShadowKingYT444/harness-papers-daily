Keyword Harnesses Fail Open: A Cheap Diagnostic Ladder for Tool-Use Claims in Small Language Models

Juan S. Santillana · published 2026-10-01 · arXiv:2610.02142

relevant

One line

A cautionary case study: keyword-matching benchmark harnesses credited a 1.1B model for tool use it never performed — matched-architecture 600M and 1B models scored identically on the lenient metric (B4 0.660 vs 0.650) while verbatim-reproduction checks showed 6/6 vs 0/6 valid tool calls — and a ladder of strict, cheap diagnostics (verbatim reproduction, first-token probes, embedding-drift checks) that gates tool-use claims.

The problem

Keyword-matching benchmark harnesses fail open: they can credit small models for tool use they never perform. The paper documents this in a matched-architecture pair of Spanish security language models — same decoder, tokenizer, and special tokens — where the lenient metric couldn't separate a model that genuinely emits tool calls from one that doesn't.

How it works

The diagnostic ladder, each rung cheap (minutes of CPU): (1) Verbatim-reproduction checks on real training examples — the 600M emits valid tool calls with generalized arguments on 6/6, the 1B on 0/6 across checkpoints. (2) First-token probe — localizes the 1B's failure to a missing prior (probability 10⁻⁴–10⁻⁵ on <|tool_call|>), and probes over 38 archived checkpoints show the web-heavy training phase erased an earlier memorized prior. (3) A targeted SFT recipe (diverse corpus, 5× higher learning rate, 2,202 steps, ~3.3 GPU-hours) repairs the 1B with three orders of magnitude fewer tokens than the failed 6B-token tool-SFT phase; valid emission rises 0.100 → 0.959 on all 269 corpus rows and beats the 600M on 238 unseen prompts (0.536 vs 0.428, p=0.004). (4) Embedding-drift check — 97.7% of the bf16 table remains bit-identical, so the repair lives in the surrounding network, not the trigger token's embedding. Both models still over-trigger on negative prompts (answering without a call only 0.09/0.17 of the time).

Key results

The headline is the false positive itself: near-identical benchmark scores (0.660 vs 0.650) hiding a total capability gap (6/6 vs 0/6). The repair recipe is the constructive result: a small, diverse, high-LR SFT phase fixes what a large tool-SFT phase broke, and the diagnostic ladder costs minutes of CPU.

How it relates to adaptive decomposition

This is the evaluation-side companion to the harness-optimization story: if the harness that measures you fails open, every harness optimizer optimizing against it is optimizing a mirage. For the user's mechanism specifically, the warning is sharp — a meta-controller that accepts/rejects component edits based on benchmark scores needs the measurement harness to be strict, or it will promote edits that game the metric rather than fix the mechanism. The first-token probe is also a nice minimal example of the kind of cheap, targeted diagnostic an agent-driven loop should run before expensive interventions: localize the fault precisely (a missing prior on one token), then intervene minimally. The paper's "fail open" framing generalizes: any harness optimizer whose acceptance criterion is lenient is a keyword harness in disguise.

Limits and open questions

Single case study on two proprietary Spanish security models (VectraYX-600M/1B) from one independent researcher — no replication across model families or tool-use domains. The repair is demonstrated on the author's own corpus; the "mostly recites" caveat on its own corpus rows suggests the repair is partly memorization. The ladder is diagnostic, not a fix for benchmark design — it tells you when a metric lies, not how to build one that doesn't.
