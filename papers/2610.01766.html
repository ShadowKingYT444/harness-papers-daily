VideoEvolve: Evolving Agent Harnesses for Video Temporal Grounding

Bingjun Luo, Yuhuan Fan, Siqi Li · published 2026-10-01 · arXiv:2610.01766

core mechanism

One line

VideoEvolve automatically evolves the agent harness around a frozen video-language model for video temporal grounding, using a "cloze-structured" representation (fixed stage interfaces, evolvable internal workflows/instructions) and branch-guided evolution that keeps a retained code branch off the champion mainline; instruction refinement is the consistent source of gains, code evolution helps unevenly.

The problem

For agents built on frozen video-language models, the harness decides how queries guide temporal predictions and how those predictions get refined — but improving it manually means diagnosing grounding failures and coordinating changes to both agent workflows and instructions, where a fix for one failure can change behavior elsewhere.

How it works

VideoEvolve's key device is the Cloze-Structured Harness Representation: the harness is organized into grounding stages (Observe → Propose → Cross-check → Arbitrate → Budget gate → Finalize) with fixed interfaces through which observations, interval hypotheses, and verification evidence pass, while the internal code and instructions of each stage are editable blanks an external coding agent can propose modifications for. Branch-Guided Harness Evolution organizes search around a current champion plus a retained code branch: a program that hasn't yet replaced the champion can still be refined off the mainline, separating continued exploration from acceptance. Execution feedback guides local edits (including near-miss repair), and a validation gate decides promotion — rejected-but-eligible candidates provide a repair path rather than being discarded. Search history serves as alternative starting points (positioned relative to DGM's archive, AutoHarness's hypothesis tree, Meta-Harness's artifact retention). Search uses 60 proposal slots / ~218k solver calls; once an endpoint is selected, deployment runs the fixed harness without the coding agent.

Key results

On ReXTime, full VideoEvolve improves R@.5 from 51.14 → 59.17 and mIoU 48.71 → 53.93; on TimeLens-Bench, 46.86 → 53.53 R@.5 and 45.68 → 50.73 mIoU. Component exchange shows evolved instructions alone and evolved code alone each help, with the full combination best — but the conditional gain from evolved code is larger on ReXTime than TimeLens-Bench, i.e. executable refinement's value is setting-dependent. Deployment costs more calls/tokens than the seed harness, with the extra compute spent revisiting existing observations. Code at github.com/bingjunluo/VideoEvolve.

How it relates to adaptive decomposition

The cloze-structured representation is a designed-in version of the decomposition question: interfaces are fixed, internals evolve. It is the middle ground between ModularRSI's five fixed modules and adaptive decomposition's discovered structure — the authors fix where decomposition boundaries are and let evolution rewrite within them. The branch-guided retention of non-champion programs is a population/archival mechanism the user's own loop could adopt: keeping a refined-but-not-yet-accepted branch is how you avoid the premature-commitment trap that kills evolutionary harness search. The finding that instruction evolution consistently helps while code evolution is uneven is directly relevant to adaptive decomposition's operator design — the fuse/split operators act on structure, and this paper suggests structural (code) edits are the brittle ones, so a discovered decomposition should probably evolve instructions aggressively and structural changes conservatively. Also notable: the validation-gated promotion with repair paths for rejected candidates is the honest acceptance discipline the Self-Evolving Harness paper lacked.

Limits and open questions

The setting-dependence of evolved code is flagged but unexplained — the paper shows code evolution helps on ReXTime and less on TimeLens-Bench without diagnosing why, which is exactly the failure-analysis gap adaptive decomposition's credit assignment would need to fill. All evidence is video temporal grounding with one frozen VLM family; whether the cloze representation ports to coding, tool-use, or GUI harnesses is untested. The 218k-solver-call search budget is heavy for a single task family, and the paper separates discovery cost from deployment cost but doesn't compare against cheaper baselines (e.g. instruction-only search with the same budget).
