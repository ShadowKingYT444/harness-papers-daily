Self-Healing Harness for Runtime Oversight of Agent Self-Modification

Sina Tayebati, Divake Kumar, Nastaran Darabi, Ranganath Krishnan, Amit Ranjan Trivedi · published 2026-09-21 · arXiv:2609.24130

highly relevant

One line

A model-agnostic runtime harness that frames persistent agent self-modification as admission control: the agent authors candidate behavioral rules from observed failures, but an external evidence gate decides which rules persist across episodes, requiring measured improvement on the triggering failure with no regression beyond a fixed margin on protected cases.

The problem

LLM agents deployed over long horizons inevitably change their own future behavior through stored memories and revised operating instructions, and there is no principled way to decide which self-generated changes should be allowed to persist. Improvement on the failure that motivated a change is insufficient: the same change can silently degrade behavior that previously worked, and individually useful updates can interact and accumulate into corpus-level drift analogous to catastrophic interference. Existing self-correction, memory, and scaffold-evolution systems (STOP, Darwin Godel Machine) either let the agent retain whatever it produces or validate only aggregate improvement, so locally-beneficial-but-globally-harmful self-modifications slip through.

How it works

The Harness wraps an otherwise unmodified agent in a Detect, Notice, Heal, Validate loop, with model weights pi held fixed and all adaptation happening to an external rule set R. Detect: an evaluation service scores each turn's trace on a three-tier metric stack (cheap progress metrics M1 run continuously; step-level M2, explanatory M3, outcome M0 only after escalation). A trajectory gate keeps a running peak per metric and flags a stall (no meaningful gain within window w=10 while below threshold theta=0.5) or a regression (score drops delta_drop=0.15 below the running peak). Notice: findings go to a mailbox in an external on-disk workspace using a pull model — nothing is injected into the conversation; the agent must explicitly retrieve it, and the standing context grows only with the number of rule files, not their content. A per-turn barrier synchronizes evaluation so a repair authored at turn i can affect turn i+1. Heal: the agent inspects the flagged trace and authors a candidate behavioral rule r, which gets provisional (within-evaluation) execution authority. Validate: promotion requires replaying captured sessions — at most 3 failure cases matched to the rule's signature and at most 2 protected (previously succeeding) cases, re-scored on M1 union M2 — and passing the admission test: the target metric improves by at least delta_prom=0.05 on some failure case while every metric on every replayed case stays above -delta_reg=0.05, with non-regression taking precedence over improvement. Where replay is unavailable, a weaker forward trial (n=3 unmatched sessions, no protected-case test) is the fallback. A corpus-level guard re-tests the whole accumulated active rule set, since individually accepted rules can interfere. Rules follow a candidate, active, retired lifecycle with an audit journal recording the evidence behind every promotion.

Key results

16 matched Baseline-vs-Harness pairs across AppWorld (168 tasks), Terminal-Bench (10 tasks), and tau-2 airline (50) and retail (114), each run with gpt-5.6-terra, gpt-5.6-luna, claude-haiku-4.5, and claude-sonnet-5 at k=4 trials. Task-completion score s-bar is numerically higher under the Harness in all 16 pairs, but only two paired bootstrap 95% intervals exclude zero: AppWorld/terra Delta=+0.022 (CI [+0.006,+0.040], p=0.010) and tau-2 retail/sonnet-5 Delta=+0.032 (CI [+0.003,+0.061], p=0.03) — all other gains are directional. pass_k (success on all 4 trials) leads or ties in all 16 pairs (12 leads, 4 ties, none lower). The agent proposed 2,306 rules, of which 1,244 were promoted and 1,062 retired (~46% rejected). The headline finding: among 383 replay-decided retirements, 211 (55%) improved their triggering failure while regressing a protected case (observed drops up to 0.60 in task_completion and 0.25 in outcome_correct) — a target-only retention rule would have admitted all 211. Replay availability varies structurally: 84-92% of validation on AppWorld and tau-2 retail, 58-72% on tau-2 airline (a replay-budget unit mismatch truncated runs), 0% on Terminal-Bench. Accumulated-adaptation risk is real: on AppWorld/luna the Harness advantage decayed from +0.017 in quartile 1 to -0.016 in quartile 4 (p=0.022) as the active set grew 13 to 70 rules and input tokens rose 1.50x to 2.52x Baseline, despite every rule passing the gate individually. Overhead: mean context 1.25x Baseline, agent turns +0.0-1.8 per trial, task spend $177.06 to $211.46 plus $92.90 repair (1.72x total), wall-clock latency up 1.7-7x.

How it relates to adaptive decomposition

This paper decomposes the update (each self-modification is an individual rule with its own admission test) but does not do adaptive decomposition: the decomposition is not discovered by the agent at all. The four-stage Detect-Notice-Heal-Validate loop and the rule representation are fixed and human-designed; the agent's only creative freedom is authoring individual rules within that fixed frame — a fixed action set, not an evolvable structure. There is no splitting of a problem into subproblems, no independent search budgets per component, no parallel improvement, no splitting failing components further, and no fusing of working ones. Its closest resonance with adaptive decomposition is the failure mode it diagnoses: individually-validated components that interfere at the corpus level (the RQ4 AppWorld/luna decay) is exactly the failure the "fuse working ones / revert when local and global correctness disagree" machinery is designed to catch. Its forward-trial path and bounded corpus guard also mirror the revert-to-monolithic-state instinct, but both are validation mechanisms over a flat rule set, not structural re-decomposition.

Limits and open questions

The paired Baseline-vs-Harness comparison has no "immediate admission" arm, so the measured gains do not isolate the effect of evidence-gating itself — only the RQ2 finding (55% of rejections were locally-good-but-globally-bad) directly motivates the gate. Protected-case coverage is sparse (at most two unranked protected cases per round), so the 211 conflicts are detected incidents, not total incidence, and the guard's guarantees cover only measured task-reliability metrics. The agent is assumed non-adversarial and cannot be defended against one that circumvents the workspace or manipulates the evaluator. All runs use seed 1 despite path-dependent adaptation, there is no held-out transfer evaluation, and synchronous oversight adds 1.7-7x latency. Open probes: relevance-ranked protected-case selection, repeated-replay verdict stability, and whether gating thresholds (delta_prom, delta_reg, w) transfer across model families.
