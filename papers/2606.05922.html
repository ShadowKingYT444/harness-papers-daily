Evolving Agents in the Dark: Retrospective Harness Optimization via Self-Preference

Wenbo Pan, Shujie Liu, Chin-Yew Lin, Jingying Zeng, Xianfeng Tang, Xiangyang Zhou, Yan Lu, Xiaohua Jia · published 2026-06-04 · arXiv:2606.05922

highly relevant

One line

RHO (Retrospective Harness Optimization): improves the full agent harness — memory, context, skills, tools — using only past unlabeled trajectories, no validation set, by selecting challenging past tasks, re-solving them in parallel, diagnosing failures with self-validation/self-consistency, and picking the best candidate harness by the agent's own pairwise self-preference.

The problem

Every existing harness-optimization method scores candidates against a labeled validation set. In real deployments, collecting a validation set that reflects the distribution of future tasks is hard or impossible. But a deployed agent naturally produces a rich stream of past trajectories. The central question: can you improve the harness for future tasks using only those past trajectories, with no ground-truth labels at all?

How it works

A single retrospective pass with four stages. (1) Coreset selection: from the pool of past trajectories, pick a small, difficulty-diverse subset of tasks using a determinantal point process (DPP) — diverse so the harness doesn't overfit to one failure mode. (2) Group rollout: re-solve each coreset task G times in parallel. (3) Diagnosis: extract two signals — self-validation (detect failures within a single trajectory) and self-consistency (disagreements across the G parallel attempts expose instability) — and use them to instruct generation of N candidate harness updates. (4) Selection: no labels; instead the agent's own pairwise self-preference ranks candidate harnesses by which one's rollouts it prefers over the baseline. The whole pipeline updates prompts, program parameters, workflow code, skills, and tools — the full harness. Straightforward experience accumulation (just dumping memories in) is beaten, and RHO beats validation-feedback evolution under a comparable budget.

Key results

  • One optimization round on software-engineering trajectories: SWE-Bench Pro pass rate 59% → 78%, with zero external grading.
  • Consistent gains across three domains: software engineering, technical work, knowledge work.
  • Analysis shows RHO designs specific skills/tools targeting prior failure modes, reshapes the agent's action patterns, and sustains higher accuracy over long-horizon sessions.
  • Each pipeline stage progressively isolates useful improvement signals (ablations on the diagnostic contributions).

How it relates to adaptive decomposition

This is the direct ancestor-style comparison for recursive harness self-improvement: RHO does failure-driven harness evolution with no labels, which is the selection half of adaptive decomposition's loop. The critical difference is the search object: RHO samples and selects whole-harness candidates as monoliths — one candidate wins, one replaces the incumbent. It never decomposes the harness into independently evolvable components, never gives subproblems separate budgets, never splits a failing component or fuses working ones, and has no monolithic-fallback logic (its only safety is the self-preference ranking). Adaptive decomposition would restructure how RHO's search space is organized: instead of N whole-harness candidates, evolve the skill that fixes the verification failure independently from the memory that fixes the context failure — and let the agent itself discover that split. RHO is also single-round; adaptive decomposition's revert-when-local-and-global-disagree mechanism has no counterpart here.

Limits and open questions

Self-preference is the load-bearing assumption: if the agent's preference judgments are biased (preferring verbose or overconfident rollouts), selection drifts — there's no external anchor. The coreset comes from past tasks, so distribution shift in future tasks is unaddressed. Only one optimization round is demonstrated; iterated rounds might compound self-preference bias or oscillate. Open: does iterated RHO converge or degrade? And can the self-consistency signal (disagreement across parallel attempts) be promoted from a diagnostic into an actual per-component failure localizer — the first step toward decomposing the harness rather than replacing it wholesale?
