Co-Harness: Co-Evolving Harnesses and Model Weights for LLM Agents

Zhengyu Chen, Teng Xiao, Huaisheng Zhu, Yige Yuan, Luan Zhang, Jingang Wang · published 2026-07-17 · arXiv:2607.22688

highly relevant

One line

Alternates between (a) an LLM critic that reads failed agent trajectories, attributes each failure to a harness component, and patches the harness, and (b) supervised fine-tuning the model on the better trajectories the improved harness produces — so scaffolding and weights bootstrap each other round after round.

The problem

Post-training for AI-research agents optimizes model parameters under a fixed, hand-designed harness (prompts, tool schemas, skills, middleware, memory) while the harness — the data-generating process that decides trajectory quality — stays outside the optimization objective. A bad tool schema, missing retry hook, short turn limit, or underspecified prompt prevents useful trajectories from being generated at all, creating a mismatch: the model is updated while the scaffolding that determines trajectory quality is never improved from the failures it causes. In tool-integrated reasoning this is a hard bottleneck: a single misconfigured component can abort an entire multi-turn code-execution episode with no signal for the model to learn from.

How it works

A harness configuration is formalized as a five-tuple φ = (P, T, S, Mid, M): prompts/templates, tool definitions and schemas, reusable skills/modules, middleware (main loop, verification hooks, context management), and long-term memory policy. One co-evolution round alternates two loops. (1) The Co-Harness Loop fixes the model θ_t, collects failed trajectories F⁻, and feeds each to HarnessCritic, an LLM prompted as an "expert agent scaffolding engineer" that emits a structured record {root_cause, harness_dim, severity, evidence, diff_suggestion} — root cause drawn from a six-class taxonomy (prompt_ambiguity, tool_schema_error, skill_missing, middleware_mismatch, memory_overflow, plus agent_error as an abstention label for model-side failures that get excluded from patching). Per-failure attributions are ranked by recurrence, severity, and consistency of the proposed field path, then merged into one local YAML diff (old value → new value, e.g. switching a thread pool to a process pool, raising max_turns, enabling a retry hook). Each candidate patch is validated by re-rollout on two held-out splits: accepted only if it fixes the target failure (δ_in > 0) without regressing anything else (δ_out ≥ 0); accepted diffs are committed to a versioned harness registry that serves as an audit trail and enables rollback. (2) The Model Alignment Loop re-runs the current model under the evolved harness, keeps trajectories that pass the task verifier, and does plain SFT on them: θ_{t+1} = argmax Σ log p_θ(τ|x) — distilling the scaffolding's behavior into weights. The updated model then exposes higher-order harness bottlenecks invisible under the weaker policy, and the next round begins. Stopping rule: no candidate patch passes validation, or marginal gain falls below threshold for consecutive rounds.

Key results

  • Core dual-loop experiment (Tool-Integrated Reasoning: math competition problems solved by interleaving chain-of-thought with a Python code interpreter; Qwen3-8B and 32B; T=2 rounds, each = HarnessCritic with K=5 inner iterations + one SFT pass): average accuracy 58.5% (Round 0, harness-only evolution) → 73.5% (Round 1) → 78.9% (Round 2), a cumulative +20.4 pp over the baseline and +24.7 pp over a human-designed static harness. Largest gain on the hardest benchmark: HMMT25 +27.2 pp for 32B (49.8→77.0), +20.1 pp for 8B.
  • 200+ hour autonomous case study: 22 harness versions with zero human intervention, starting from a crashed config (vLLM KV-cache error in 32 s). Phase 1 fixed engineering failures (tool-schema patch, ThreadPool→ProcessPool zombie-thread fix: 0%→59.6%); Phase 2 found an 8.7× inference speedup (3.78 h→1.11 h) via global-batched inference while restoring accuracy (61.5%); Phase 3 discovered a 6-trajectory majority-vote ensemble of two seeds reaching 63.3% within a 3.33 h budget — and correctly rolled back a prompt regression that cost ~16.5 pp.
  • Compounding conditions named explicitly: harness debt is reduced (not increased) — the model trained on evolved-harness trajectories performs better at test time, showing genuine skill transfer, e.g. 8B AIME25 56.9→78.3% (+21.4 pp).
  • Failure modes of the loop itself are reported: SFT plateau (8B on AIME24 saturated at 84.7 vs 84.0 — model-side ceiling), harness over-patching (too much early complexity overwhelms a weaker model), attribution cascade (a fix introducing a new bug; the registry rolls back). Attribution accuracy degrades for failures needing counterfactual control-flow reasoning.
  • No explicit HarnessCritic-vs-human attribution accuracy number is reported in the main text; the human annotation protocol (2 experts, κ=0.77 agreement on 200 trajectories) exists to ground the taxonomy, but the paper does not claim a measured match rate — treat critic quality as unmeasured on paper, evidenced only downstream through round-over-round gains.

How it relates to adaptive decomposition

This is the closest mechanism encountered so far to the agent discovering its own scaffolding — relevance 4. The HarnessCritic loop is failure-driven, not catalogue-driven: a patch is attempted when recurring, attributed failure evidence demands it, and rolled back when validation re-rollout shows a regression, which is the same revert-on-disagreement logic adaptive decomposition uses. It also improves components in parallel via the (P, T, S, Mid, M) decomposition, and the "skill_missing" attribution class is exactly the loop noticing it needs a new reusable decomposition primitive. But the differences are sharp: the five dimensions of decomposition are fixed and human-designed (the critic cannot invent a sixth axis, reorganize the architecture, or split a failing component into subcomponents on its own); there is no independent search budget per component and no fusion of working pieces; and the Model Alignment loop SFTs the whole model on the whole trajectory set rather than improving components independently. In short: the agent discovers which patches to apply and when to revert, but within a fixed taxonomy and fixed loop structure — it is agent-driven repair of a fixed decomposition, not agent-discovered decomposition.

Limits and open questions

The loop needs a capable critic LLM, a minimum volume of failure trajectories to cold-start, and substantial compute for multi-round SFT; only two full co-evolution rounds are actually run (T=2) and most gains land in Round 1 (+15.0 pp) vs Round 2 (+5.4 pp), so whether compounding continues beyond round 2 is untested. All experiments are one narrow domain — TIR math benchmarks (AIME, HMMT) — where failures are binary and easy to attribute; nothing shows it working for open-ended agent harnesses (coding agents, research assistants) where failure attribution is far fuzzier. Structural harness redesign stays human; online/within-run adaptation is future work. The biggest probe for adaptive decomposition: does the critic's fixed five-class taxonomy eventually bottleneck the loop (it can't invent a sixth dimension), and would letting the agent propose new harness dimensions produce the same compounding?
