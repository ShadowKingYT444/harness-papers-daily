Robo-Harness K1: Harnessing Robot-Use Agents via Perception Augmentation

Zexi Li, Yehang Zhang, Wenqian Li, Haojian Huang, Chenxu Wang, Shiyuan Deng, Yangkai Wei, Tianyi Zhang, Binghui Xie, Bohan Zhou, Yifan Chang, Kaiwen Zhou, Ying-Cong Chen, James Cheng, Yinchuan Li · published 2026-09-24 · arXiv:2609.29389

background

One line

A hand-designed perception toolkit (region grounding, calibrated depth/geometry, anchor tracking, grasp candidates) exposed as tools so a frozen VLM can do robot manipulation without any action-head training — a harness paper, but no harness optimization.

The problem

VLMs understand objects and spatial relations but can't turn that into manipulation: VLA models need huge demonstrations and their action heads damage the VLM's pretrained visual features; RGB-only "robot-use agents" force the VLM to infer metric 3D geometry from pixels, which is beyond what RGB can support; adding depth as a new modality needs invasive retraining. The missing piece is accessible perceptual evidence.

How it works

K1 exposes four perception tool families through the VLM's existing image+language interface, behind a tool interface with the raw depth kept hidden: (i) region grounding — find_regions/inspect_region via SAM 3 with persistent identifiers overlaid on the original image; (ii) depth & geometry — measure_depth (calibrated back-projection from pixel to metric 3D), fit_geometry (planes/principal directions), region_relation, with measurement overlays drawn on RGB; (iii) anchor tracking — TAPNext++ tracks point correspondences across frames, lifted to world coordinates with validity flags; (iv) grasp candidates — GraspGen proposes parallel-jaw poses projected onto the RGB view, the agent picks one. The MDP splits tool calls into reasoning steps (gather evidence, no state change) and action steps (move_relative with 3cm/axis bounds, move_to_pose, set_gripper), with a decision note per call for faithful student supervision. Training: SFT (language-side LoRA, vision frozen) of Qwen3.5-9B on teacher tool-call traces — next-token prediction aligns naturally with tool-call sequences, unlike raw action regression.

Key results

  • LIBERO-PRO: Gemini 3.7 Flash + K1 reaches 77.8%, beating GPT-6 Astra RGB-only at 61.1%; K1 lifts Astra to 88.9%.
  • Zero-shot transfer: Gemini+K1 to three RoboSuite arms (~90%/88.8%/86.2%) and dual-arm RoboTwin (32% Easy, 28% Hard — only a 4-point drop, vs RDT 47.6→19.2% and π0 64.0→25.2% under perturbations), no target fine-tuning.
  • Qwen3.5-9B trained on just 107 teacher episodes: 44.2% on new-state generalization (vs 30.2% OpenVLA) and 13.9% on held-out tasks where every VLA baseline scores 0.0%.

How it relates to adaptive decomposition

Barely — but instructive as a fixed-decomposition success story. K1's interface is a crisp, human-designed decomposition of the manipulation problem (perception queries vs action commits; four perceptual sub-families with persistent identity anchors as the interface). It shows that when the decomposition is right, a frozen model + good tools beats learned action heads — the argument for investing in decomposition design. But nothing is searched or evolved: the decomposition is an engineering choice frozen before evaluation. For adaptive decomposition, K1 is a data point that a well-chosen decomposition is powerful — the open question is whether an agent can discover one this good on its own.

Limits and open questions

No optimization or adaptation of the harness — everything is hand-built, so it can't fix itself when tools mislead (e.g., bad SAM masks, depth noise). The 13.9% held-out-task number, while better than zero, is still low in absolute terms. All evaluation is in simulation (LIBERO, RoboSuite, RoboTwin) — no real-robot results. I'd probe how the harness degrades under sensor noise and whether a learned policy could learn to choose which perception tools to call rather than the current fixed tool schema.
