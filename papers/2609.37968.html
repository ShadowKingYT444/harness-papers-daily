SelfSearch: Reward-Free Search for Self-Improving Agents

Day 41 · Nov 09, 2026

SelfSearch: Reward-Free Search for Self-Improving Agents

Jungwoo Yang, In Jin Kong, Yohan Jo · published 2026-09-29 · arXiv:2609.37968

core mechanism

One line

Drops the downstream-evaluation loop from agent search entirely: agents revise their own full repository across ten generations guided only by records of previous self-improvement episodes — the reasoning, tool actions, and outcomes of earlier edits — and still improve population-mean success in every model–benchmark setting.

The problem

Existing self-improvement search ties the improvement signal to downstream tasks: every candidate gets evaluated on a dev set, so search cost grows with task coverage and the search is hostage to the evaluated distribution. SelfSearch asks whether the experience of self-modification itself — not task-solving experience — can be a sufficient improvement signal.

How it works

  • Self-improvement episode. The whole agent repository (instructions, tools, policy library, orchestration) is editable; weights stay fixed. In episode k, agent Bₖ gets an editable copy of its repo plus read-only episode records Eₖ from prior episodes — trajectories of reasoning, tool calls and outcomes, plus the code changes made. It edits and verifies the repo; the successor Bₖ₊₁ performs the next episode, so improvements to tools/procedures change how later self-modification itself is done. The model–tool interaction loop and inference settings live in a fixed runtime outside the editable repo, with trajectory capture runtime-managed. No downstream benchmark tasks or rewards are used during search; evaluation happens only after checkpoints are frozen.
  • Two parallel lineages with shared records. Ten generations, two lineages with qualitative search directions: capability (find limitations revealed by inefficient behavior/failed actions; build reusable tools) and adaptive (improve how the agent revises its approach when evidence contradicts its plan). Both lineages see both episode records from the previous generation, so discoveries cross-pollinate while implementations stay separate. All checkpoints are archived; the final agent of each lineage is evaluated (no dev-score selection).
  • Models: GPT config (gpt-5.6-sol for self-improvement, gpt-5.6-luna for downstream) and DeepSeek config (deepseek-v4-pro-0813 / deepseek-v4-flash-0731). Baselines: the initial agent B₀ (derived from DGM's released implementation), plus two evaluation-guided baselines (linear search, archive search) using a ten-task SWE-bench dev set.
  • The discovered changes are concrete tooling: text search with output limits, line/character-range file viewing, structured trajectory readers with call/result linking, exact-text replacement, output limits on trajectories and diffs — with lineages borrowing and refining each other's tools across generations (e.g., one lineage's clipped-output failure motivates the other's search tool, which is then refined after its own reader reveals excerpt-combination blowups).

Key results

  • Population-mean success improves over the initial agent in all six model–benchmark settings (2 configs × SWE-bench Verified / SWE-bench Multilingual / Terminal-Bench 2.1).
  • Terminal-Bench 2.1: capability agent 43.8% → 55.1% (+11.2 pp) with GPT; 65.2% → 73.0% with DeepSeek. SWE-bench Multilingual: +6.7 pp (GPT), +5.0 pp (DeepSeek). SWE-bench Verified: 81.7% → 86.7% for both DeepSeek lineages.
  • Efficiency: DeepSeek adaptive agent gains 5.0 pp on SWE-bench Multilingual while cutting cost 38.5% on tasks solved by both initial and evolved agents; cost reductions of 19.7–36.1% (DeepSeek) and 8.7–13.6% (GPT) on shared successes in SWE-bench Verified.
  • Competitive with evaluation-guided search at lower cost: matches or exceeds linear/archive search success on most settings, with search cost 13.4–53.2% cheaper (GPT: $6.52 vs $7.53–$12.35; DeepSeek: $4.03 vs $7.90–$8.59).
  • Nine-harness comparison on Terminal-Bench 2.1 (DeepSeek V4 Flash): SelfSearch's capability agent solves 73/89 (82.0%), tying the top-scoring harness, Codex — at $4.03 search cost.
  • Cross-model transfer: evolved implementations improve over the initial agent in both transfer directions (GPT-found agents run on DeepSeek V4 Flash: 83.3%/85.0% vs 81.7%; DeepSeek-found on GPT-5.6 Luna: 79.2%/76.7% vs 75.0%).
  • Ablations: removing episode records costs −2.1/−2.9 pp of mean success; fixing the improver at B₀ costs −1.7/−2.9 pp — both records and the evolving improver contribute. Evolved tools are reused downstream: line-range viewing on ~34–40% of tasks, text search on 8.6–23.6%.

How it relates to adaptive decomposition

This is the closest existing process analog to adaptive decomposition: frozen weights, full-repo self-modification, parallel independently-evolving variants, compounding improvements across generations — a genuine recursive harness-improvement loop. But it is recursion without decomposition: each lineage edits the repository as one monolithic unit; there is no mechanism for the agent to discover components, split a failing piece, fuse two working ones, or allocate search budget per component. The two lineages are the only "modularity," and they're human-fixed with human-fixed directions. Two specific lessons carry over. First, the evolving-improver ablation (fixed improver loses ~2 pp) is evidence that the meta-level — how the agent improves its improving — matters, which is exactly the level adaptive decomposition operates at (the decomposition policy is itself the evolvable object). Second, SelfSearch's lineages freely copy each other's episode records — an archive-based cross-pollination that adaptive decomposition's independent per-component budgets could borrow, since the paper shows it works without collapsing diversity. And a caution in the other direction: SelfSearch succeeds without any selection pressure during search, which suggests adaptive decomposition's per-component fitness budgets aren't strictly necessary — but without them it also has no mechanism to retire failing branches, so it inherits the unbounded-growth risk the dichotomy paper's Corollary 4 flags.

Limits and open questions

"Reward-free" is doing heavy lifting: there is no downstream-task reward, but agents still use local tool outcomes and self-checks as a verification signal, and the qualitative search directions plus the human-refined prompt templates (refined over pilot searches) encode substantial prior about what counts as an improvement. The final checkpoint is chosen with no selection criterion at all — just the last generation — so we see one realized trajectory per setting, not the expected outcome; the authors flag consistency across independent searches as future work. Results are on coding-agent benchmarks only; nothing shows the reward-free signal works in domains where "inspectability of your own editing process" doesn't transfer to the task. The evolved tools (line-range viewing, exact-text replacement) resemble known good agent–computer interfaces, so part of the gain may be rediscovering interface best practices rather than task-specific mechanism discovery. I read the full main text plus the appendices on environment, prompts, and setup; appendix tables on detailed costs were skimmed.
