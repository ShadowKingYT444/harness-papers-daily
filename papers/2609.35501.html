SRHarness: A Harness for Agentic Symbolic Regression

Day 49 · Nov 17, 2026

SRHarness: A Harness for Agentic Symbolic Regression

Zihan Yu, Shixuan Zhou, Hao Huang, Jingtao Ding, Yong Li · published 2026-09-28 · arXiv:2609.35501

context

One line

A carefully engineered, domain-specific harness for LLM-driven symbolic regression whose composable scientific actions, persistent hypothesis state, and trajectory lifecycle management deliver large symbolic-recovery gains with no search over the harness itself.

The problem

In agentic symbolic regression, the LLM is promoted from equation-proposer to search controller, but prior systems bundle the supporting runtime — action interfaces, hypothesis memory, trajectory management — into strategy-specific scaffolding, so benchmark comparisons conflate differences in search strategy with differences in harness quality. SRHarness asks whether the harness itself, as an independent runtime layer, can be the decisive factor in long-horizon scientific discovery.

How it works

SRHarness separates three layers — base model, search strategy, and harness — and implements the harness through three mechanisms:

1. Composable scientific actions. An action is written r = A(q; κ), where q holds the agent-chosen scientific arguments and κ the harness-managed execution context (data bindings, train/validation splits, runtime config). Action arguments can be expression-based views over data — a raw variable xᵢ, a transformed view like log xᵢ or xᵢ/xⱼ, or a candidate-derived view like the residual y − f(x) — so intermediate quantities flow between heterogeneous actions without rebuilding datasets. Candidate-producing actions follow a shared candidate–evidence contract (expression, evaluation, complexity, evidence, provenance) with common validity semantics before admission, and each action separates its machine-readable result from a compact model-facing observation.

2. Persistent scientific state. Admitted hypotheses live in structured state Sₜ outside the conversational transcript, surviving restarts and abandoned branches. The model sees only a bounded projection vₜ = P_ρ(Sₜ): a fit–complexity Pareto view and a Top-k view, exposing compact subsets of the accumulated search state.

3. Trajectory lifecycle management. The harness coordinates continuation, branching, restart, and termination with provenance tracking. The reference implementation instantiates this as a configurable R×C×L×K scheduler (restart rounds × independent branches × refinement depth × local response samples); at each restart a Top-k view of the persistent state seeds the new conversation. In the experiments the action set (statistics analysis, relationship analysis, evaluate/submit formula, constant fit, call PySR, call SINDy, code executor) and the R1-C1-L30-K1 schedule are fixed; there is no optimization of the harness itself.

Key results

Evaluated on LLM-SRBench (240 problems: LSR-Synth and LSR-Transform, plus a new anonymized LSR-Transform-Anon track that strips all scientific descriptions and variable names):

  • LSR-Transform symbolic accuracy (DeepSeek-v4-flash-0731): 93.69% vs 62.16% for SR-Scientist, 45.05% LLM-SR, 48.65% IGSR — with the lowest expression complexity (14.64) among matched methods. All methods reach NMSE ~10⁻¹⁴, so the gain is genuinely structural recovery, not fitting.
  • LSR-Transform-Anon: 72.97% symbolic accuracy vs 39.64% for SR-Scientist; SA retention 78% (vs 28% for LLM-SR/IGSR, 64% SR-Scientist), showing the advantage isn't just semantic-recall of known laws.
  • vs Codex under the same DeepSeek-v4-flash-0731 backbone: 72.97% vs 20.72% — a pure harness effect with the model held fixed, reaching parity with Codex on GPT-5.5 (68.47%). Giving Codex the same scientific tools directly hurt it (68.47% → 64.86%) while increasing runtime and tokens — the value is in the integration, not the tool list.
  • LSR-Synth OOD accuracy: physics 78.00%, chemistry 78.87%, biology 87.09%, materials 96.00%; symbolic accuracy 6.20% vs <1% for matched LLM baselines; 11.11 min/problem (vs 57.67 for LLM-SR).
  • Ablations: restricting to a bare code executor costs ~6 pp (74.47% → 68.47%); disabling expression-based views costs ~7 pp (→ 67.57%); Pareto view vs best-formula-only costs ~8 pp (74.47% → 66.67%); deep refinement beats reallocating budget to restarts/branches (R1-C1-L30-K1 74.47% vs more restarts 66.67%).

How it relates to adaptive decomposition

SRHarness is an existence proof that harness design can dominate model and tool choice in agentic performance — the same lesson adaptive decomposition bets on — and its persistent-state-with-projection design is genuinely useful machinery: bounded model-facing views over an accumulating archive are how you'd want cross-generation memory to look. But it is the opposite of adaptive decomposition in the key sense: everything is fixed and human-designed (action set, projection policy, R×C×L×K schedule), the harness never changes, and the agent never discovers any decomposition of anything. There is no per-component search budget that adapts to evidence (the R/C/L/K allocation is a fixed hyperparameter grid), no splitting or fusing, and no recursion. It's a strong reference point for what a hand-built harness buys; the open question it raises for adaptive decomposition is whether an agent-discovered harness can match this level of performance without the domain engineering.

Limits and open questions

Everything here is symbolic regression; it's unclear how much of the design (candidate–evidence contracts, Pareto projections, R×C×L×K) transfers to general agent tasks versus being domain-tuned. Baselines were re-run under a token-aligned rather than call-count-aligned budget, which the authors defend but which means the numbers aren't directly comparable to the baselines' own published figures. The fixed-schedule search never adapts its budget allocation to the problem — a place where an adaptive scheme would be expected to win, but that comparison isn't made. I only read the main text plus the appendix methodology; detailed per-backbone efficiency tables live in the appendix and weren't fully audited.
