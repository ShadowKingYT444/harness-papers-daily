AutoRef: Harness Optimization for Agentic Multi-Reference Image Generation

Day 33 · Nov 01, 2026

AutoRef: Harness Optimization for Agentic Multi-Reference Image Generation

Yuta Oshima, Ku Onoda, Yusuke Iwasawa, Masahiro Suzuki, Yutaka Matsuo, Hiroki Furuta · published 2026-09-28 · arXiv:2609.35530

context

One line

AutoRef automatically optimizes the executable harness code around frozen image-generation and reasoning models for multi-reference image generation, using train/validation task separation plus beam search, discovering a harness that makes open-weight FLUX.2 klein 4B competitive with proprietary models.

The problem

Multi-reference image generation (combine several reference images into one coherent new image) is hard: models omit or duplicate subjects, or paste them in unnaturally. Agentic image pipelines wrap a generator and a reasoning model in a harness — executable code specifying how references are interpreted, prompts built, candidates generated/diagnosed, and the final image selected — but in the multi-reference case, references play different roles (identity, garment, background, style) and outputs must satisfy many criteria at once, so good harnesses are hard to design by hand, and human-written ones vary widely. Simple agentic refinement on top of a strong generator gives only limited gains. Meanwhile existing harness optimizers assume verifiable rewards (math/coding), while image generation relies on noisy perceptual evaluators.

How it works

Freeze both models (generator Gφ, reasoning model Mθ) and optimize only the harness program H that calls them: (y, τ) ∼ H(Mθ, Gφ, x). Each iteration, a coding-agent proposer P (Claude Fable 5.1 via Claude Code CLI) reads the current beam and full search history L (harness code, scores, evaluator rationales, execution trajectories, generated images — including rejected candidates') and writes K=4 new harness programs. Two design choices adapt this to noisy visual evaluation: (1) task separation — search tasks are split into disjoint Dtrain and Dval; Dtrain feedback enters L for proposals, while Dval is used only to rank candidates, and its scores/artifacts are never exposed to the proposer; (2) iterative beam search with B=2 — the two candidates with highest validation score become the next parents (parents don't compete again), and the proposer is told which survived but not their scores. Five search iterations on 48/48/133 train/val/test split of four-reference MultiBanana tasks discovered AutoRef-Harness: it draws three images total — draft A from a scene-described-per-subject prompt and draft B from a "keep the background/style reference as canvas, paint subjects into it" prompt, both reference-grounded (Mθ assigns each requested element to its reference, excluding unrequested content); Mθ picks the better draft; Mθ lists up to five concrete complaints naming the reference each concerns and rewrites the prompt for draft C; failure-aware selection picks by counting hard failures (missing/duplicate reference, wrong background) first, with pairwise Mθ judgment only on ties, and a later draft replaces the incumbent only if it wins in both presentation orders.

Key results

On held-out four-reference MultiBanana test (scores /10, mean of five metrics): FLUX.2 klein 4B + AutoRef-Harness goes 5.72 → 7.37, beating all open models and matching/exceeding Nano Banana Pro (7.20), GPT-Image-1.5 (7.07), Seedream 4.5 (7.03). The same harness transfers without re-optimization to 3-reference (6.94 → 7.76) and 5-reference (5.19 → 6.36) settings, to FLUX.2 9B (5.78 → 7.10) and Qwen-Image-Edit-2511 (4.44 → 5.69), to OmniContext with the GPT-4.1 evaluator, to open-weight Qwen3-VL-32B as reasoning model (5.72 → 6.90), and adds to fine-tuning gains (DyRef). Ablations: removing structurally diverse drafts −0.36, complaint-directed revision −0.38, failure-aware selection −0.44; grounding-only 6.91 with one image, selection-only 6.15. Human evaluation: 70% win vs base 4B, competitive with Nano Banana Pro (46% win / 40% loss). Search-method comparison (same budget/generator/reasoner/evaluator): AutoRef > Greedy Search > Meta-Harness, with Meta-Harness and Greedy finalists also drawing more images (4.2 and 5 vs 3); even AutoRef's second-best harness beat both methods' finalists — evidence that train/val separation and the multi-parent beam each add value. One failure mode: with Qwen-Image-Edit at five references the generator itself fails and the harness can't compensate.

How it relates to adaptive decomposition

The harness here has a fixed human-defined stage structure (interpret references → construct prompts → generate drafts → diagnose → select); the agent (proposer) can rewrite arbitrary code, but it does not discover a decomposition of the problem into subproblems, and there are no independent per-subproblem search budgets, no parallel component improvement, no splitting of failing components, and no fuse/revert logic. What the paper does contribute to adaptive decomposition is search design around noisy evaluation: separating feedback tasks from selection tasks to prevent overfitting, and keeping a beam of multiple parents instead of a single incumbent — a weak analog of maintaining independent lineages. Notably, the paper also reports no gain-consolidation problem: the discovered harness is one composed pipeline whose stages all ablate positively. But that pipeline is small (four components) and domain-specific; the consolidation question from 2609.28908 (whether independent gains fuse into one harness) is simply never stressed here. Relevance 2: a useful exemplar of how to run harness search under noisy rewards, not a comparable decomposition mechanism.

Limits and open questions

The harness can't exceed the generator's capability ceiling (fails where the generator itself fails); everything is maximized against a single VLM evaluator (transfer to GPT-4.1 suggests but doesn't prove this isn't evaluator overfitting); and the whole study is one domain with human-seeded initial harnesses (vanilla generator + GEMS) and only five search iterations, so we don't know how far the beam search scales or whether it plateaus like the 72-generation run in 2609.28908. Interesting probes for adaptive decomposition: would per-stage independent search budgets (e.g., optimize the complaint-rewriter and the selector on separate feedback loops) find components the joint search missed? And would the paper's success survive a task where the right stage structure itself must be discovered rather than filled in?
