EvoGen-Harness: Learning Where and How to Evolve Image-Generation Harnesses

EvoGen-Harness: Learning Where and How to Evolve Image-Generation Harnesses

Jiabin Luo, Yinan Liu, Chunlei Meng, Yufei Guo · published 2026-09-30 · arXiv:2610.00383

highly relevant

One line

EvoGen-Harness evolves multi-responsibility harnesses around frozen text-to-image generators (instead of optimizing one predefined dimension like prompts or routing), with Trace — Trajectory-Relative Attribution and Coordinated Evolution — attributing failures to the right harness responsibility across stochastic executions; it beats the strongest single-dimension baselines by +0.2633 on GenEval2, +0.0720 on T2I-CompBench++, +0.0752 on WISE, with 94.8% No-Patch accuracy and only 1.9% regression.

The problem

Frozen T2I generators can be improved by evolving the external harness (prompting, routing, workflows, tool use), but existing approaches fix one predefined dimension in advance, restricting where failures can be corrected. Opening up multiple generator-external responsibilities creates the attribution problem: visual feedback reveals what failed, not where persistent evolution should occur or how to explore that space efficiently.

How it works

EvoGen-Harness is generator-agnostic and lets multiple harness responsibilities evolve. Its engine is Trace (Trajectory-Relative Attribution and Coordinated Evolution): it aggregates evidence across K stochastic executions of the same request, uses failure attribution as a search prior to focus candidate updates on the responsible harness layer, and progressively re-attributes residual failures to coordinate evolution across responsibilities as fixes land. Held-out validation plus regression checks prevent unnecessary or harmful updates (hence the 94.8% No-Patch accuracy — knowing when not to patch — and 1.9% regression rate).

Key results

Across GenEval2, T2I-CompBench++, and WISE, EvoGen-Harness improves over the strongest evaluated single-dimension baselines by +0.2633, +0.0720, and +0.0752 respectively. Attribution recall is 87.9–91.4%, No-Patch accuracy 94.8%, regression rate 1.9%.

How it relates to adaptive decomposition

The attribution question is exactly adaptive decomposition's credit-assignment problem, transplanted to image generation: given a failure, which harness component is at fault? Trace's trajectory-relative attribution across stochastic executions is a concrete mechanism the user's system could borrow — repeated rollouts of the same scenario to localize blame, rather than a single trace. The "No-Patch" accuracy metric is the honest version of the validation gate: a good meta-controller must know when no component deserves blame, which is precisely the failure mode (acceptance without validation) flagged in the Self-Evolving Harness work. The deeper resonance: the paper's argument that fixing one dimension in advance restricts the correction space is the user's argument for agent-discovered decomposition, one level up — here the dimensions are harness responsibilities, there they are harness components. The contrast: responsibilities here are still a fixed, human-enumerated set (prompting, routing, workflows...); the system learns where to evolve, not what the where's are. Adaptive decomposition's next step is discovering the responsibility set itself.

Limits and open questions

Attribution recall of 87.9–91.4% means 9–12% of failures are misattributed — and misattributed blame drives edits to the wrong responsibility, a failure the paper's regression rate suggests is controlled but not eliminated. The responsibility taxonomy is fixed and human-designed, so "multi-responsibility" is bounded by the authors' enumeration. All evidence is T2I generation; whether trajectory-relative attribution works for long-horizon agentic tasks with sparse rewards is untested. The 1.9% regression is measured on the paper's own held-out protocol — no adversarial or distribution-shifted evaluation.
